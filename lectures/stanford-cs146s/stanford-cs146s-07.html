Overview ​

الأسبوع الرابع في CS146S عنوانه "Customizing Your Agent and Repository"، والـ syllabus بيحدد تلات مواضيع: CLAUDE.md وAGENTS.md وإيه يتحط فين، والـ hooks للـ lint gates والـ test runs والـ guardrails، والـ subagent patterns (planner / implementer / reviewer) [cs146s2026]. المحاضرة دي (التلات 2026-10-13) هي النص النظري، والخميس كان guest lecture لـ Boris Cherny، اللي عمل Claude Code [cs146s2026] (مش متغطي هنا).

الفكرة اللي بتربط المحاضرة كلها: عشان توصل لأقصى إنتاجية مع الـ coding agents، لازم تمسك الـ stack بتاعك بإيدك، وفيه آليات كتير للتخصيص [cs146s-1013].

مافيش transcript منشور، فاللي منسوب للمحاضرة هنا هو اللي على الـ slides بس. الـ slides بتاعة الـ hooks والـ subagents قصيرة، فالشرح التفصيلي لإزاي الـ hooks بتشتغل جاي من وثائق Claude Code ومكتوب كده.

Learning objectives ​

  • تفرّق بين API وMCP وskill: مين بيستخدم كل واحد، ولإيه.
  • تصمم AGENTS.md كويس بحسب إرشادات المحاضرة.
  • تشرح ليه الـ hooks "deterministic"، وتكتب hook بيمنع تعديل ملف محمي وhook بيعمل format بعد التعديل.
  • تعرف الـ exit codes بتعمل إيه، وليه exit 1 مابيمنعش حاجة.
  • تختار الآلية المناسبة (AGENTS.md، hook، skill، subagent، MCP) لكل احتياج.

Prerequisites ​

  • The Anatomy of a Modern Coding Agent: المكونات دي كلها اتعرفت هناك بسرعة، ومنها الـ hooks.
  • MCP, Tool Calling, and Beyond: أساس جزء الـ MCP هنا.

Key ideas ​

1. APIs vs MCP vs skills ​

المحاضرة بتبدأ بمقارنة تلات حاجات بيتلخبطوا في بعض [cs146s-1013]:

WhatWho uses itUsage
APIsواجهات HTTP/REST/GraphQL الـ app بيعرضها للمطورينإنت، أو SDKإنت اللي بتقرر الـ auth والـ retries والـ pagination والـ validation
MCPtool definitions بيعرضها server عشان الـ agent ينادي عليها بطريقة standardالـ model/agent runtime كـ tool calls، مش مطور بيكتب integration جديد كل مرةالآلية الأساسية للتعامل مع resources وdata وservices برا
Skillstask packages قابلة لإعادة الاستخدام بتعلّم الـ agent يعمل شغلانة، غالبًا بتنسيق أكتر من toolالـ agent كقدرة أعلى مستوىworkflow abstraction: "here's the repeatable way to complete X"

وبعدها slide عن مميزات زيادة للـ MCP: auth سلس، وإن الـ versioning والـ updates سهلة، وportability بين الـ clients، وsandboxing طبيعي للقدرات في الـ remote MCP [cs146s-1013]. التفاصيل في Model Context Protocol.

2. Four ways to customize an agent ​

الـ slide اللي بتلخص المحاضرة بتعدّد أربع تقنيات [cs146s-1013]:

  1. Agent behavior files (CLAUDE.md / AGENTS.md)
  2. Hooks
  3. Skills
  4. Subagents

ومعاهم MCP servers كطريقة توصّل الـ agent بالعالم برا (§7).

3. Designing an optimal AGENTS.md ​

المحاضرة بتوصف AGENTS.md على إنه "README for agent"، وبتقترح هيكل [cs146s-1013]:

  • project overview: خريطة للـ codebase
  • build and test commands (المثال على الـ slide: "use maven instead of gradle")
  • code style guidelines
  • testing instructions
  • security considerations
  • gotchas خاصة باللغة أو الـ stack (المثال: "React 18 with Typescript, Vite NOT React")

وإرشادات للكتابة [cs146s-1013]:

  • خلي التعليمات universally applicable قدر الإمكان.
  • ابعد عن الـ code snippets، لأنها بتبقى outdated بسرعة.
  • خلي بالك من الطول: أقل من 300 سطر.
  • الـ repos الكبيرة تستخدم nested configuration files، والـ AGENTS.md اللي في الـ root يبقى router، زي سطر "For more details about API gateway design, refer to docs/API-GATEWAY.md".
  • نفس المبادئ تنطبق على CLAUDE.md.

والـ slide فيها ملاحظة عن ترتيب التحميل: CLAUDE.md بيتحمل من الـ root لأقرب ملف، فالتعليمات الأقرب للشغل بتيجي الآخر قدام الموديل [cs146s-1013]. ومثال حقيقي متشاور عليه: AGENTS.md بتاع Next.js.

قواعد الاكتشاف والتحميل بالتفصيل لكل أداة في Agent Instruction Files.

4. Hooks: what the lecture says ​

الـ slide بتعرّف الـ hooks على إنها "Deterministic scripts that run on predefined event types"، وبتذكر PreToolUse وPostToolUse وUserPromptSubmit وPreCompact "…and more" [cs146s-1013]. والـ use cases [cs146s-1013]:

  • sanitize الـ user prompt
  • block sensitive actions
  • تشغيل linter أو formatter على الكود المتولد
  • تشغيل الـ tests بعد ما المهمة تخلص

وإنها مدعومة في Claude Code وCursor [cs146s-1013].

ليه "deterministic"؟ (شرح) CLAUDE.md تعليمات للموديل، والموديل هو اللي بيقرر يلتزم ولا لأ. لو كتبت "شغّل Ruff بعد أي تعديل"، غالبًا هيعمل، بس ممكن ينسى. الـ hook بيخلي الـ harness نفسه هو اللي بينفذ، فالتنفيذ مش متوقف على قرار الموديل. وثائق Claude Code بتقول نفس المعنى: الـ hooks "deterministic control" عشان حاجات معينة تحصل دايمًا بدل ما تعتمد على إن الـ LLM يختار يعملها [cc-hooks-guide]. ومقالة Anthropic اللي في قراءات الأسبوع بتفرّق: الـ command والـ HTTP والـ mcp_tool hooks بتشتغل deterministically، إنما الـ prompt والـ agent hooks بتستخدم حكم موديل [segner2026].

5. How hooks work in Claude Code ​

القسم ده كله من وثائق Claude Code، مش من الـ slides.

Where they live. الـ hooks بتتعرّف في ملفات settings بصيغة JSON: ~/.claude/settings.json لكل مشاريعك، و.claude/settings.json للمشروع (ينفع يتعمله commit)، و.claude/settings.local.json للمشروع من غير مشاركة، ومعاهم managed policy والـ plugins وfrontmatter بتاع الـ skills والـ subagents [cc-hooks].

Three levels. event (زي PreToolUse)، وبعدين matcher group بيفلتر إمتى يشتغل (زي "للـ Bash tool بس")، وبعدين handler واحد أو أكتر [cc-hooks]. الـ handler ممكن يكون shell command، أو HTTP endpoint، أو MCP tool، أو prompt، أو agent [cc-hooks].

Matchers. في أحداث الأدوات، الـ matcher بيتطابق على اسم الأداة. Edit|Write معناها Edit أو Write بالظبط. لو فيه رموز تانية بيتعامل معاه كـ JavaScript regex مش anchored، فـ Edit.* هتطابق NotebookEdit كمان [cc-hooks].

Input. الـ command hook بياخد JSON على الـ stdin فيه session_id وcwd وhook_event_name، وفي أحداث الأدوات tool_name وtool_input. في Edit وWrite، مسار الملف في tool_input.file_path [cc-hooks].

Events. الـ reference فيه أكتر من 30 event [cc-hooks]. أشهرهم:

EventWhen it firesCan exit 2 block?
UserPromptSubmitبعد ما تبعت الـ prompt وقبل ما Claude يعالجهأيوه، الـ prompt مابيوصلش
PreToolUseقبل أي tool callأيوه، بيمنع الـ call
PostToolUseبعد tool call نجحلأ، الأداة اشتغلت خلاص؛ الـ stderr بيوصل لـ Claude
Notificationلما Claude Code يبعت notification (مثلًا محتاج permission)لأ
Stopلما Claude يخلص الردأيوه، بيخليه يكمّل
PreCompactقبل الـ compactionأيوه، بيمنع الـ compaction

Exit codes. هنا أكتر غلطة شائعة [cc-hooks]:

Exit codeMeaning
0نجاح. أي JSON مطبوع على الـ stdout بيتطبق، والـ action بيكمّل. ده مش موافقة: الـ permission flow العادي بيكمّل زي ما هو
2blocking error. في الأحداث اللي تقدر تمنع، الـ action بيقف، والـ stderr بيبقى السبب اللي Claude بيشوفه
أي رقم تانيnon-blocking error. الـ action بيكمّل، وبيظهر notice في الـ transcript

يعني hook بيعمل exit 1 عشان "يرفض" عملية خطيرة مابيمنعش حاجة. لازم exit 2، أو JSON فيه decision.

Paths. استخدم ${CLAUDE_PROJECT_DIR} عشان تشاور على scripts المشروع من غير ما تعتمد على المكان اللي Claude شغال فيه دلوقتي، ويُفضّل exec form (command + args) مع أي path placeholder [cc-hooks].

6. Skills and subagents on the slides ​

Skills: "frequently-used prompts as files that the agent can execute"، والـ use cases: تشغيل الـ tests، وعمل plan، والبحث، ومراجعة الكود، والتحقق من الـ outputs [cs146s-1013]. والـ slide فيها كمان ملاحظات إن المحاضر هيعرض أمثلة: "ship-it" command في Claude Code، و"deslop" command من Cursor [cs146s-1013].

Subagents: "runtime delegation"، والهدف منهم [cs146s-1013]:

  • فصل نضيف بين الـ contexts بتاعة شغلانات مختلفة
  • الـ subagent بيرجّع "only final message"
  • الاسم والوصف وقايمة الأدوات بيتحملوا من أول الـ session
  • بيتنادوا implicitly أو explicitly
  • يأتمتوا أكتر الـ workflows تكرارًا

والـ use cases: استكشاف الـ codebase، وتبسيط الكود بعد تغيير، واختبار الـ app end-to-end، و"perfect for side tasks". وملاحظة على الـ slide بتقارنهم بـ CLAUDE.md اللي "more about anchoring behavior" [cs146s-1013]. التفاصيل في Subagents.

8. The context story ​

آخر slide قبل الأسئلة بتعدّد الطبقات اللي بتكوّن الـ context بتاع الـ agent [cs146s-1013]: system prompt، وMemory.md، ومعلومات البيئة، وأدوات الـ MCP، والـ skills، وAGENTS.md (global)، وAGENTS.md (local).

My reading: ده نفس الدرس اللي في Agent Harness: كل آلية تخصيص بتدفع من نفس الـ context window، فالسؤال دايمًا "إيه اللي يستاهل يبقى موجود في كل request؟". والـ hooks استثناء مثير: بتأثر على السلوك من غير ما تاخد مكان في الـ context إلا لما ترجّع حاجة.

Technical example ​

hook بيمنع تعديل ملفات محمية (قبل التنفيذ)، وhook بيعمل format بعد التعديل. الـ config في .claude/settings.json بتاع المشروع؛ الجزء التاني مأخوذ من مثال Prettier في الـ docs [cc-hooks-guide]:

json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "python",
            "args": ["${CLAUDE_PROJECT_DIR}/.claude/hooks/protect_files.py"]
          }
        ]
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "jq -r '.tool_input.file_path' | xargs npx prettier --write"
          }
        ]
      }
    ]
  }
}

والـ script:

python
# .claude/hooks/protect_files.py
import json
import sys
from pathlib import PurePath

PROTECTED = (".env", "config/production.env")

data = json.load(sys.stdin)
path = PurePath(data.get("tool_input", {}).get("file_path", "")).as_posix()

if any(path == p or path.endswith("/" + p) for p in PROTECTED):
    print(f"Blocked: {path} is a protected file", file=sys.stderr)
    sys.exit(2)  # blocks the tool call; stderr goes back to Claude

sys.exit(0)  # no decision: the normal permission flow applies

الـ script ده اتجرّب محليًا (Python 3.12) بـ JSON مشابه للي الـ hook بياخده: Edit على config/production.env طبع السطر ده وخرج بـ exit code 2، وWrite على src/api/users.py خرج بـ 0.

text
Blocked: /repo/config/production.env is a protected file

ده مثال تعليمي، مش حماية جاهزة: الـ agent ممكن يعدّل نفس الملف بـ Bash (echo ... > .env)، والـ matcher هنا على Edit|Write بس. الحماية الحقيقية من الـ permissions والبيئات المعزولة، والـ hook طبقة زيادة.

Limitations and open questions ​

  • مافيش transcript، فالأمثلة اللي المحاضر عرضها حية (الـ "ponytail hooks"، وposts بتاعة Boris Cherny اللي متشاور عليها) مش معروف تفاصيلها.
  • Deterministic ≠ infallible. الـ hook بيتنادى كل مرة الـ event يطابق، بس الـ script نفسه ممكن يفشل، والـ matcher ممكن مايغطيش كل الطرق لنفس التأثير (زي Bash بدل Edit).
  • PostToolUse مايقدرش يلغي حاجة حصلت خلاص [cc-hooks-guide].
  • الـ hook مش بديل عن CI: الاختبارات اللي لازم تنجح قبل الـ merge مكانها CI والـ branch protection، لأن الـ hook بيشتغل على جهاز اللي شغّل الـ agent بس.
  • سؤال مفتوح: إمتى التعليمة تتنقل من CLAUDE.md لـ hook؟ المقالة في القراءات بتقترح قاعدة: لو السلوك لازم يحصل كل مرة، يبقى hook [segner2026].

Exercises ​

Exercise: Instruction or hook

لكل واحدة قول: CLAUDE.md ولا hook؟ (1) "المشروع بيستخدم FastAPI وPostgreSQL". (2) "شغّل ruff format على أي ملف Python بعد تعديله". (3) "ماتعدّلش أي حاجة في migrations/ من غير ما تسأل". (4) "فضّل composition على inheritance". (5) "ابعتلي notification لما تحتاج permission".

Solution

(1) CLAUDE.md: معلومة ثابتة. (2) hook (PostToolUse على Edit|Write): لازم يحصل كل مرة. (3) hook (PreToolUse) أو permission rule، لأنه guardrail. (4) CLAUDE.md: محتاج حكم، مش قاعدة آلية. (5) hook على Notification.

Exercise: Fix the guard

زميلك كتب PreToolUse hook بيطبع "Denied" ويعمل exit 1 لما الـ agent يحاول يعدّل .env. جرّبه ولقى إن التعديل حصل برضه. ليه؟ وإزاي يصلحه؟

Solution

exit 1 non-blocking error: الـ action بيكمّل، وبيظهر notice بس [cc-hooks]. لازم exit 2 والسبب على الـ stderr (أو JSON فيه permissionDecision: "deny"). وكمان يفكر في Bash: الـ matcher على Edit|Write مش هيمسك echo ... > .env.

Exercise: Write a router AGENTS.md

monorepo فيه api/ (Python) وweb/ (TypeScript) وinfra/ (Terraform). اكتب هيكل AGENTS.md في الـ root بإرشادات المحاضرة.

Solution

ملف قصير (أقل من 300 سطر): overview للـ repo وخريطة للتلات أجزاء؛ أوامر الـ build والـ test العامة؛ قواعد عامة بتنطبق على كله؛ وسطور router زي "For API conventions, see api/AGENTS.md" و"For frontend, see web/AGENTS.md". من غير code snippets، والتفاصيل الخاصة بكل stack في الملف بتاعه [cs146s-1013].

Review questions ​

  1. إيه الفرق بين API وMCP وskill من حيث مين بيستخدمه؟
  2. ليه المحاضرة بتنصح بإن AGENTS.md يبقى أقل من 300 سطر ومن غير code snippets؟
  3. ليه الـ hook "deterministic" والتعليمة في CLAUDE.md لأ؟ وإيه حدود الكلمة دي؟
  4. إيه اللي بيحصل لو PreToolUse hook خرج بـ 0، وبـ 1، وبـ 2؟
  5. ليه PostToolUse مايقدرش يمنع حاجة؟
