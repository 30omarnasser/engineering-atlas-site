Building a Minimal Coding Agent ​

ReviewedPublishedAI-assisted

Week 1 of CS146S: a coding agent like Claude Code is, at its core, an LLM in a loop that asks for tools which ordinary code executes; built from scratch with three file tools in about 200 lines of Python.

Overview ​

أدوات زي Claude Code وCursor بتحسسك إنها سحر: تكتبلها طلب بالإنجليزي، فتقرا ملفاتك وتعدّل المشروع وتكتب كود شغال. المحاضرة الأولى في CS146S بتشيل الغطاء ده: الـ core بتاع الأدوات دي مش سحر، ده حوالي 200 سطر Python واضحين [eric2026post]. وعشان كده المحاضر بيبدأ الكورس بيه: عشان تستخدم الـ coding agents صح، لازم تفهم هي متبنية إزاي [cs146s-0922].

الفكرة كلها في جملة واحدة من الـ slides: المستخدم بيتعامل مع coding agent client، والـ client بيشغّل loop مع LLM، وأحيانًا الـ LLM بيطلب tool calls والـ client هو اللي بينفذها برا الموديل ("off-LLM") [cs146s-0922].

Where this lecture sits

الكورس بيقول عن نفسه إنه "about principles not tools" [cs146s-0922]. المحاضرة دي هي الأساس اللي كل الباقي مبني عليه: الـ harness في المحاضرة الجاية (The Anatomy of a Modern Coding Agent) هو نفس الـ loop دي بس بمكونات أكتر حواليها.

Learning objectives ​

  • تشرح الفرق بين LLM بيرد في الشات وcoding agent بيعدّل ملفات فعلًا.
  • تبني coding agent بتلات tools من الصفر: registry، وtool descriptions، وparser، وnested loops.
  • تتتبع كل رسالة بتدخل الـ conversation history في تشغيل حقيقي.
  • تعدّد مشاكل النسخة البسيطة اللي تمنعها تبقى production-ready، وتعرف إزاي تصلّحها.

Prerequisites ​

  • Python: functions، dictionaries، json، وpathlib.
  • فكرة عامة عن الـ LLM APIs (بتبعت messages وبترجع نص).
  • المفهومين دول هيتشرحوا هنا، وليهم صفحات مستقلة لو حابب تتعمق: Agent Loop وTool Calling.

Key ideas ​

1. An LLM suggests; an agent acts ​

لو طلبت من LLM عادي "اعمل ملف calculator.py فيه function للجمع"، هيكتبلك الكود في الشات وخلاص. مافتحش ملف ومعدّلش حاجة. الـ coding agent بقى بيعمل كده:

  1. الموديل بيقرر إنه محتاج tool، ويرد بطلب منظم (tool call).
  2. الكود بتاعك بينفذ الطلب ده محليًا، يعني بيعمل الملف فعلًا.
  3. النتيجة بترجع للموديل.
  4. الموديل يكمّل أو يرد رد نهائي.

وده كل الـ loop. والجملة اللي تحفظها من المقال: الموديل عمره ما بيلمس الـ filesystem؛ هو بيطلب إن حاجات تحصل، والكود بتاعك هو اللي بيخليها تحصل [eric2026post].

LLM = بيفكر ويقترح. Agent = LLM + Tools + Loop.

الـ slide بتلخص البنا في أربع خطوات [cs146s-0922]:

3. Three tools are enough ​

الـ agent محتاج تلات قدرات بس عشان يعمل حاجات كتير مفيدة: يقرا ملف، يشوف محتوى folder، ويعدّل أو ينشئ ملف [eric2026post]. الـ slides بتسميهم "Read_file" و"List_dir" و"Edit_file" [cs146s-0922]، والكود في المقال بيسميهم read_file وlist_files وedit_file [eric2026post].

4. The tool registry and tool descriptions ​

الـ tool registry هو dictionary بيربط الاسم اللي الموديل بيكتبه بالـ function الحقيقية:

python
TOOL_REGISTRY = {
    "read_file": read_file_tool,
    "list_files": list_files_tool,
    "edit_file": edit_file_tool,
}

بس الموديل مش بيشوف كود Python. لازم نوصفله الأدوات. الفكرة الذكية في كود المحاضر المنشور إن الوصف بيتولّد من الـ function نفسها: الوصف من الـ docstring (__doc__)، والـ parameters من inspect.signature()[eric2026post]. يعني الـ docstring بتاع الـ function بقى documentation للموديل، مش بس للمبرمج.

python
import inspect

def get_tool_str_representation(tool_name: str) -> str:
    tool = TOOL_REGISTRY[tool_name]
    return f"Name: {tool_name}\nDescription: {tool.__doc__}\nSignature: {inspect.signature(tool)}"

الكود ده مكتوب بأسلوب المقال، مش منسوخ حرفيًا. ولاحظ إن الـ type hints بتوضح للموديل شكل الـ arguments، بس Python مابيعملش validation ليها وقت التشغيل.

5. The system prompt defines a protocol ​

الـ system prompt بيعمل حاجتين: بيقول للموديل هو مين وعنده أنهي أدوات، وبيحدد بروتوكول: لو عايز أداة، رد بسطر واحد بالظبط بالشكل tool: TOOL_NAME({JSON_ARGS}) ومن غير أي كلام تاني، والـ JSON يكون مضغوط في سطر واحد بـ double quotes، وبعد رسالة tool_result(...) كمّل المهمة [eric2026post].

ليه صيغة ثابتة؟ لأن البرنامج محتاج يفرّق بين "الموديل بيتكلم" و"الموديل بيطلب أداة" بقاعدة بسيطة يقدر يطبقها بالكود.

Why the post writes the format with double braces

في الكود المنشور الـ prompt string عادي بيتملا بـ .format()، فالـ braces اتكتبت مضاعفة {{JSON_ARGS}} عشان str.format يطبعها braces عادية بدل ما يعتبرها placeholder. اللي بيوصل للموديل هو {JSON_ARGS} [eric2026post].

6. Parsing the reply ​

extract_tool_invocations() بتعمل العكس: بتحوّل نص الموديل لبيانات Python. بتلف على السطور، وأي سطر بيبدأ بـ tool: بتقطع منه اسم الأداة والـ JSON، وتعمل json.loads، وتطلع list فيها tuples (name, args) [eric2026post]:

python
[("read_file", {"filename": "main.py"})]

ولو حصل أي خطأ في السطر، الكود الأصلي بيعمل except Exception: continue [eric2026post]. السطر ده بريء في الشكل، بس الـ lab أثبت إنه بيعمل silent failure خطير (هنرجعله تحت).

7. Two nested loops ​

الـ agent فيه loop جوه loop [eric2026post]:

  • Outer loop: بيستقبل طلب جديد من المستخدم ويضيفه للـ conversation. Ctrl+C أو EOF بيطلّع من البرنامج بشكل منظم بدل ما يقع بـ traceback.
  • Inner loop: بينادي الموديل، ويشوف فيه tool calls ولا لأ. لو مفيش: يطبع الرد ويعمل break من الـ inner loop بس، ويرجع يستنى المستخدم. لو فيه: ينفذ كل أداة، ويضيف النتيجة، ويلف تاني.

الـ inner loop هي اللي بتخلي الـ agent يعمل أكتر من خطوة ورا بعض: يقرا ملف، وبعدين يعدّله، وبعدين يأكد [eric2026post]. طلب واحد من المستخدم ممكن يعمل أربع calls للموديل وتلات tool executions (كل رد مش نهائي فيه tool call واحد على الأقل)، وكل ده جوه دورة واحدة من الـ outer loop.

8. The tools themselves ​

resolve_abs_path بتحوّل أي مسار نسبي لمسار كامل بالنسبة للـ folder الحالي، وبتفهم ~. بس مش بتتأكد إن المسار جوه المشروع؛ يعني الموديل ممكن يطلب ../ ويوصل لأي حتة.

read_file_tool بترجع dictionary فيه المسار والمحتوى، مش string بس، عشان الموديل يعرف أنهي ملف اتقرا بالظبط.

list_files_tool بتستخدم iterdir()، فبتعرض المستوى الحالي بس. الموديل يستكشف المشروع خطوة خطوة: يشوف الـ root، وبعدين يطلب folder معين.

edit_file_tool أهم واحدة، لأنها اللي بتغيّر حاجات فعلًا [eric2026post]:

old_strWhat happensRisk
"" (empty)new_str بيتكتب كمحتوى الملف كله، والنتيجة created_fileلو الملف موجود، محتواه القديم بيتمسح

الـ count = 1 في replace بيقلل التعديلات غير المقصودة، بس مش بيضمن إن أول ظهور هو اللي الموديل قصده. وعشان كده الأفضل إن old_str يكون نص مميز مايتكررش في الملف (ملاحظة شرح، مش من المحاضرة).

9. Dispatch and feeding results back ​

بعد الـ parsing، الـ dispatch بسيط: TOOL_REGISTRY[name]، وبعدين نادي الـ function بالـ arguments المناسبة، وضيف النتيجة للـ conversation كرسالة user محتواها tool_result(...) [eric2026post].

ليه user مش role خاص بالأدوات؟ لأن في التصميم ده مفيش native tool calling؛ النتيجة ببساطة "رسالة جديدة داخلة للموديل" ومتميزة بالنص tool_result. الـ APIs اللي بتدعم native tool calling عندها صيغة رسمية بـ id بيربط النتيجة بالطلب (شوف Tool Calling).

A detail the notes caught

في الكود المنشور، رد الـ assistant بيتضاف للـ history بس لما يكون رد نهائي. لما الموديل يطلب أداة، طلبه نفسه مش بيتحفظ؛ اللي بيتحفظ هو النتيجة بس [eric2026post]. فالموديل في الـ call اللي بعده بيشوف tool_result(...) من غير ما يشوف هو طلب إيه. ده شغال في الأمثلة البسيطة، بس بيخلي الـ history ناقصة. الـ lab بيضيف كل الردود.

Technical example ​

الـ re-implementation كاملة وقابلة للتشغيل في الـ lab Minimal coding agent. ده قلب الـ inner loop منها:

python
while True:
    reply = llm(conversation)
    conversation.append({"role": "assistant", "content": reply})
    calls = extract_tool_invocations(reply)
    if not calls:                                   # no tool call: final answer
        print(f"Assistant: {reply}")
        break                                       # leaves the inner loop only
    for name, args in calls:
        result = TOOL_REGISTRY[name](**args)        # KeyError if the model invents a tool
        conversation.append({"role": "user", "content": f"tool_result({json.dumps(result)})"})

والـ output الحقيقي للـ happy path:

text
  [tool] read_file -> ok
  [tool] edit_file -> edited
Assistant: Done. I added multiply(a, b) to hello.py.
  roles: ['system', 'user', 'assistant', 'user', 'assistant', 'user', 'assistant']

From 200 lines to a production tool ​

المقال نفسه بيقول إن الأدوات زي Claude Code بتضيف: error handling أحسن، وstreaming، وcontext management أذكى (زي تلخيص الملفات الطويلة)، وأدوات أكتر (تشغيل أوامر، بحث في الكود)، وapproval workflows للعمليات اللي بتمسح. بس الـ core loop هو هو [eric2026post].

Limitations and open questions ​

  • المحاضرة بتبني الـ core بس. مفيش تشغيل أوامر shell، ولا tests، ولا permissions، ولا context management. المحاضرة الجاية بتتكلم عن المكونات دي.
  • الـ text protocol هش: الـ JSON لازم يبقى في سطر واحد. الموديل اللي بيكتب JSON على كذا سطر هيضيع طلبه.
  • سؤال مفتوح: الموديل بيعرف إمتى يقف إزاي؟ في التصميم ده، الإشارة الوحيدة إن الرد مافيهوش tool call. مفيش طريقة يقول بيها "أنا مش متأكد" أو "محتاج إذن".

Exercises ​

Exercise: Rebuild it without looking

اكتب الـ agent من الصفر من غير ما تنسخ من المقال أو الـ lab: registry، وtool descriptions من الـ docstrings، وparser، وnested loops. جرّبه بموديل scripted زي اللي في الـ lab.

Solution

اتأكد من حاجتين بالذات: (1) الـ break بيطلّع من الـ inner loop بس، (2) كل نتيجة أداة بتتضاف للـ history قبل الـ call اللي بعده. قارن الـ output بتاعك بالـ happy path فوق: لازم تشوف نفس الـ 7 roles لو بتضيف كل الردود.

Exercise: Add a fourth tool safely

ضيف أداة run_command(command: str). إيه الضوابط اللي لازم تحطها قبل ما تسمح للموديل يستخدمها؟

Solution

على الأقل: allowlist للأوامر المسموحة أو تأكيد من المستخدم قبل كل أمر، وتشغيل جوه الـ workspace بس، وtimeout، وحد أقصى لحجم الـ output اللي يرجع للموديل (عشان مايملاش الـ context). وده بالظبط نوع الـ "approval workflows for destructive operations" اللي المقال بيقول إن الأدوات الحقيقية بتضيفه.

Exercise: Switch to native tool calling

حوّل الـ agent يستخدم native tool calling بدل الـ text protocol. إيه اللي بيتشال من الكود، وإيه اللي لسه لازم يفضل؟

Solution

بيتشال: الـ system prompt الخاص بالصيغة، والـ regex parser. بيفضل: الـ registry، والـ dispatch، والـ validation للـ arguments، وإضافة النتيجة للـ history (بالـ id بتاع الـ call)، وشروط الوقف.

Review questions ​

  1. لما الموديل يطلب read_file، مين اللي بيفتح الملف فعلًا؟ وليه ده مهم للأمان؟
  2. ليه فيه loop جوه loop؟ إيه اللي بيحصل لو شلنا الـ inner loop؟
  3. إزاي inspect.signature() والـ docstring بيخلوا وصف الأدوات مايختلفش عن الكود؟
  4. إيه اللي بيحصل لو old_str فاضي في edit_file، والملف موجود؟
  5. ليه except Exception: continue في الـ parser أخطر من crash؟
  6. اذكر تلات حاجات بتفرّق Claude Code عن الـ 200 سطر دول.
