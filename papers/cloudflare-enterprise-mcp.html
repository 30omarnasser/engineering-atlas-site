Scaling MCP adoption: Cloudflare's enterprise MCP reference architecture ​

ReviewedPublishedAI-assisted

Cloudflare بتشرح إزاي بتدير MCP جوه الشركة: remote servers مركزية، وCloudflare Access للـ auth، وMCP server portals للـ discovery والصلاحيات والـ DLP، وCode Mode بأداتين بدل 52، وAI Gateway للتكلفة، وCloudflare Gateway لاكتشاف الـ shadow MCP.

In one paragraph ​

بناء MCP server سهل. الصعب إن مئات الموظفين في كل الأقسام يستخدموا عشرات الـ servers على بيانات الشركة من غير ما الصلاحيات تتبعتر، ومن غير ما الـ tokens تنفجر. Cloudflare بتحكي هي عملت إيه جوه الشركة: شالت الـ local servers وخلّت فريق مركزي ينشر remote servers من template فيه الضوابط جاهزة، وحطت قدامهم MCP server portal واحد بيعمل discovery وصلاحيات وDLP وlogging، وضافت Code Mode اللي بيلم كل الأدوات في أداتين، وحطت AI Gateway بين الـ client والموديل، واستخدمت Cloudflare Gateway عشان تلاقي الـ MCP servers اللي الناس بتوصلها من ورا الـ portal [goldberg2026]. المقال وصف لتجربة الشركة وفي نفس الوقت إعلان عن منتجاتها، فلازم نفرّق بين الاتنين وإحنا بنقرا.

Learning objectives ​

  • تشرح ليه Cloudflare اعتبرت الـ local MCP servers خطر، وإيه البديل.
  • تفرّق بين Cloudflare Access وMCP server portal وAI Gateway وCloudflare Gateway وAI Security for Apps.
  • تشرح Code Mode على الـ portal وتقرا رقم الـ 94% بالشرط اللي معاه.
  • تشرح يعني إيه shadow MCP وإزاي بيتكشف، وحدود الكشف ده.

Problem ​

الـ MCP بقى منتشر في Cloudflare برا الـ engineering كمان: product وsales وmarketing وfinance. والمخاطر اللي المقال بيسميها: authorization sprawl، وprompt injection، وsupply chain risks [goldberg2026].

والـ local servers بالذات كانت مشكلة: ممكن تيجي من مصادر ونسخ محدش راجعها، فبتزوّد خطر الـ supply chain attacks والـ tool injection، وفريق الأمن مايقدرش يديرها، وكل موظف بيقرر يشغّل إيه ويحدّثه إمتى. المقال بيقولها صريحة: "This is a losing game" [goldberg2026, Remote MCP servers provide better visibility and control].

وفيه مشكلة تانية: التكلفة. الطريقة المعتادة أداة لكل API operation، ودي بتملا الـ context window بسرعة، خصوصًا لمنصات فيها آلاف الـ endpoints [goldberg2026, Code Mode with MCP server portals reduces costs].

Method ​

ده مقال reference architecture، مش تجربة. الـ "method" هو التصميم نفسه، طبقة طبقة.

1. Centrally managed remote servers ​

فريق مركزي بنى منصة MCP مشتركة جوه الـ monorepo. الموظف اللي عايز يعرض resource داخلي بياخد موافقة من فريق الـ AI governance، وبعدين ينسخ template، ويكتب تعريفات الأدوات، وينشر. والـ template بيدّيه ببلاش: write controls مقفولة افتراضيًا (default-deny) مع audit logging، وCI/CD متولد أوتوماتيك، وsecrets management. الـ CI/CD بينشرهم كـ remote servers على custom domains، وده بيدّي visibility على مين بيستخدم إيه، مع تحكم في مصدر الكود [goldberg2026, Remote MCP servers provide better visibility and control].

الفكرة المهمة إن الـ governance جوه المنصة نفسها، مش خطوة زيادة، وده حسب المقال اللي خلّى الانتشار سريع: server جديد محكوم بياخد دقايق.

2. Cloudflare Access for authentication ​

فيه servers قدام resources عامة (زي server الـ documentation) ومتاحة لأي حد، وفيه servers قدام resources خاصة. للتانيين، الـ template بيستخدم Cloudflare Access كـ OAuth provider: بيتحقق من الـ SSO والـ MFA وattributes زي الـ IP والمكان والـ device certificates [goldberg2026, Cloudflare Access provides authentication].

خلي بالك من الفرق: الـ authentication بيجاوب "إنت مين؟"؛ إنت مسموحلك تعمل إيه ده سؤال تاني، وده الـ portal بيجاوب على جزء منه.

3. MCP server portals ​

لما عدد الـ servers كبر، المشكلة بقت الـ discovery. الموظف بيوصل الـ MCP client بتاعه بالـ portal، والـ portal بيوريه كل الـ servers (الداخلية والـ third-party) المسموحله بيها. وفوق كده: logging مركزي، وpolicy enforcement ثابت، وDLP rules تمنع داتا معينة (زي PII) توصل لـ servers معينة [goldberg2026, MCP server portals centralize discovery and governance].

والـ policies بتحدد مين يدخل الـ portal، وأنهي أدوات من كل server تظهر. مثال المقال: portal لفريق الـ finance بيعرض الأدوات الـ read-only بس من server الـ code repository، وportal تاني لفريق الـ engineering على أجهزة الشركة بيعرض أدوات read/write أقوى لنفس الـ server [goldberg2026, MCP server portals centralize discovery and governance].

وفيه claim من Cloudflare إن الـ portal والـ server والـ Access بيشتغلوا على نفس الجهاز الفيزيائي في شبكتهم، فالـ traffic مابيخرجش منه. ده وصف vendor لأداء منتجه، مش حاجة المقال قاسها قدامنا.

My reading: إن الأداة ماتظهرش في الـ portal ده تحكم في الـ exposure. بس الـ server نفسه لازم يرفض العمليات اللي المستخدم مالوش صلاحية عليها، لأن الإخفاء لوحده مش authorization. والـ template بتاعهم بيعمل جزء من ده بالـ default-deny write controls.

4. Code Mode with portals ​

المقال بيبدأ الجزء ده بجملة: "We've also started to think most people are doing MCP wrong" [goldberg2026, Code Mode with MCP server portals reduces costs]. وبدل ما كل أداة تتعرض، كل الـ servers اللي ورا الـ portal بيتلمّوا في أداتين:

  • portal_codemode_search: بتدي الموديل function اسمها codemode.tools() بترجّع تعريفات كل الأدوات من كل الـ servers، والموديل بيكتب JavaScript يفلترها، من غير ما كل الـ schemas تدخل الـ context.
  • portal_codemode_execute: بتدي الموديل proxy object اسمه codemode فيه كل أداة كـ function، والموديل بيكتب JavaScript يناديهم ويربطهم ويفلتر النتايج ويتعامل مع الـ errors.

والكود ده بيتنفذ في sandbox على الـ portal بيشتغل بـ Dynamic Workers [goldberg2026, Code Mode with MCP server portals reduces costs].

مثال المقال: لاقي Jira ticket وحدّثه بمعلومات من Google Drive. الأول search:

javascript
// portal_codemode_search
async () => {
  const tools = await codemode.tools();
  return tools
    .filter(t => t.name.includes("jira") || t.name.includes("drive"))
    .map(t => ({ name: t.name, params: Object.keys(t.inputSchema.properties || {}) }));
}

وبعدين execute واحد بيربط العمليات:

javascript
// portal_codemode_execute
async () => {
  const tickets = await codemode.jira_search_jira_with_jql({
    jql: 'project = BLOG AND status = "In Progress"',
    fields: ["summary", "description"]
  });
  const doc = await codemode.google_workspace_drive_get_content({
    fileId: "1aBcDeFgHiJk"
  });
  await codemode.jira_update_jira_ticket({
    issueKey: tickets[0].key,
    fields: { description: tickets[0].description + "\n\n" + doc.content }
  });
  return { updated: tickets[0].key };
}

(نفس كود المقال، مع تعديل علامات التنصيص المائلة اللي في الـ HTML لعلامات عادية.) ده tool call اتنين بس. من غير Code Mode، الموديل كان هياخد الـ schemas الكاملة لكل أدوات الـ servers الاتنين من الأول، ويعمل تلات tool calls منفصلة [goldberg2026, Code Mode with MCP server portals reduces costs]. وبيتفعّل بإنك تضيف ?codemode=search_and_execute لـ URL الـ portal. والـ sequence نفسه مرسوم في MCP, Tool Calling, and Beyond.

5. AI Gateway ​

AI Gateway متحط على الوصلة بين الـ MCP client والـ LLM: بيخليهم يبدّلوا بين LLM providers بسرعة (عشان مايبقوش مربوطين بـ vendor واحد)، وبيحط حد لعدد الـ tokens اللي كل موظف يقدر يصرفها [goldberg2026, AI Gateway provides extensibility and cost controls].

6. Shadow MCP detection with Cloudflare Gateway ​

الـ shadow MCP زي الـ shadow IT: موظف بيوصل الـ agent بتاعه بـ remote MCP server من غير ما يعدّي على الـ portal. Cloudflare Gateway (الـ secure web gateway بتاعهم) بيدوّر على الـ traffic ده بطبقات [goldberg2026, Cloudflare Gateway discovers and blocks shadow MCP]:

  • Hostname: بالـ selector اسمه httpHost، لـ hostnames معروفة زي mcp.stripe.com، ولـ subdomains شكلها mcp.*.
  • URL path: بالـ selector اسمه httpRequestURI، لـ paths زي /mcp و/mcp/sse.
  • Body inspection (DLP): لأن MCP بيستخدم JSON-RPC، كل request فيه field اسمه method. فيه regex rules لـ initialize وtools/call وtools/list وresources/read وprompts/get وغيرهم، ولـ "protocolVersion".
javascript
// Two of the article's DLP patterns
{ name: "MCP Tools Call", regex: '"method"\\s{0,5}:\\s{0,5}"tools/call"' },
{ name: "MCP Initialize Method", regex: '"method"\\s{0,5}:\\s{0,5}"initialize"' },

والـ profile ده ممكن يعمل block أو redirect أو log بس.

My reading: الـ MCP specification revision 2026-07-28 (بعد المقال بـ 3 شهور ونص) شال الـ handshake بتاع initialize/notifications/initialized ونقل الـ protocol version لـ _meta في كل request [mcp-spec]. فالـ rules اللي معتمدة على initialize أو على key اسمه "protocolVersion" غالبًا مش هتمسك traffic بالـ spec الجديد، لكن tools/call وtools/list لسه هيمسكوه. وأي traffic مش متشاف (encrypted من غير inspection، أو stdio server شغال local) برا الكشف ده أصلًا.

7. Public-facing servers ​

Cloudflare عندها كمان servers عامة لعملاها. وبما إن كل remote MCP server هو HTTP endpoint، بيتحط ورا الـ WAF، وميزة AI Security for Apps بتفحص الـ traffic الداخل بحثًا عن prompt injection وتسريب داتا حساسة، وبتعمل topic classification. والمقال بينصح كل شركة تنشر MCP servers رسمية لمنتجاتها، عشان العملا مايجيبوش servers مش متراجعة من repositories عامة [goldberg2026, Public-facing MCP Servers are protected with AI Security for Apps].

Results ​

The 94% claim ​

لما الـ portal الداخلي متوصل بـ أربع MCP servers داخلية بس، بيعرض 52 أداة تعريفاتهم بتاكل حوالي 9,400 token. مع Code Mode، الـ 52 بيبقوا أداتين portal بحوالي 600 token، يعني تخفيض 94% [goldberg2026, Code Mode with MCP server portals reduces costs]. والمقال بيقول كمان إن التكلفة دي "stays fixed" مهما ضفت servers.

قراية نقدية:

  • الرقم ده لتعريفات الأدوات بس، عند setup واحد (4 servers). مش تكلفة المهمة كلها: الـ search بيرجّع تعريفات وأسماء parameters، والـ execute بيرجّع نتايج، ودول بيدخلوا الـ context برضه.
  • "stays fixed" claim منطقي من التصميم (أداتين ثابتتين)، بس مفيش قياس في المقال بعدد servers أكبر.
  • المقال بيفكّر بـ claim قديم إن Cloudflare API MCP server وفّر 99.9% بنفس الأسلوب؛ مارجعتش للمقال القديم أتأكد.
  • المقارنة مع رقم Anthropic (98.7% في مثال واحد) في MCP, Tool Calling, and Beyond؛ الرقمين من setups مختلفة ومش قابلين للمقارنة ببعض.

Cloudflare's own summary ​

المقال بيختم بأربع حاجات عملوها [goldberg2026, The future of MCP in the enterprise]: template لبناء remote servers بـ Access للـ authentication؛ وصول identity-based عن طريق الـ portals؛ تحكم في التكلفة بـ AI Gateway وCode Mode؛ واكتشاف الـ shadow MCP بـ Gateway. والتوصية: ابدأ بإنك تحط الـ servers الموجودة ورا MCP server portals وتفعّل Code Mode. وده في الآخر توصية بمنتجاتهم.

Limitations ​

Stated by the authors: المقال مابيذكرش حدود. هو وصف لتجربتهم وتوصية بمنتجاتهم.

My assessment:

  • Vendor source: كل المكونات منتجات Cloudflare، والمقال بيوصفها من غير مقارنة ببدائل. الأفكار (remote servers محكومة، وportal مركزي، وprogressive tool disclosure، وmonitoring) تنفع تتعمل بأدوات تانية.
  • رقم واحد مقاس: الـ 94% هو القياس الوحيد، ولـ setup واحد.
  • Detection gaps: الكشف معتمد على إن الـ traffic بيعدّي على الـ gateway وممكن يتفحص، ومعتمد على شكل البروتوكول وقت كتابة المقال (شوف الـ spec الجديد فوق).
  • Code execution: الـ sandbox بيقلل مخاطر تشغيل كود الموديل، بس مش بديل عن الصلاحيات والتأكيد قبل العمليات الخطيرة. والمقال ماتكلمش عن ده في الـ execute.
  • Prompts are not enforcement: تعليمة زي "ماتمسحش" للـ agent مش ضابط. الضابط هو إن الأداة ماتبقاش متاحة أو الـ server يرفض. ده مبدأ عام مش من المقال، والمقال بيطبقه بالـ default-deny writes والـ portal policies.

Exercises ​

Exercise: Name the component

لكل موقف قول أنهي component بيحله: (1) موظف وصّل Cursor بـ mcp.somevendor.com من غير موافقة؛ (2) عايز تمنع أرقام بطاقات توصل لـ server خارجي؛ (3) موظف صرف tokens كتير جدًا الشهر ده؛ (4) واحد من برا الشركة بيحاول يوصل لـ server الـ wiki الداخلي.

Solution

(1) Cloudflare Gateway (shadow MCP). (2) DLP rules على الـ MCP server portal. (3) AI Gateway (حد tokens لكل موظف). (4) Cloudflare Access (authentication قدام الـ server الخاص).

Exercise: Read the 94% carefully

زميلك بيقول: "Code Mode بيوفر 94% من تكلفة أي agent". اكتب تلات جمل تصحح بيها الكلام ده.

Solution

الـ 94% لتعريفات الأدوات بس، مش لكل الـ tokens في المهمة. واتقاس في setup واحد: portal متوصل بأربع servers فيهم 52 أداة. والـ search والـ execute لسه بيرجّعوا تعريفات ونتايج بتدخل الـ context، فالتوفير الفعلي بيعتمد على المهمة.

Exercise: Design portals for two teams

عندك server قدام نظام الـ tickets فيه search_tickets وget_ticket وupdate_ticket وdelete_ticket. صمم portal لفريق الـ support وportal لفريق الـ admins، وقول الحماية اللي لازم تفضل في الـ server نفسه.

Solution

Support: search_tickets وget_ticket وupdate_ticket. Admins: الأربعة، على أجهزة الشركة بس. وفي الـ server: تحقق من صلاحية المستخدم في كل call (مش بس إخفاء الأداة)، وaudit log لكل كتابة، وتأكيد أو موافقة بشرية قبل delete_ticket.

Review questions ​

  1. ليه Cloudflare اعتبرت الـ local MCP servers "a losing game"؟
  2. إيه الفرق بين اللي Access بيعمله واللي الـ portal بيعمله؟
  3. Code Mode على الـ portal بيقلل الـ tokens إزاي؟ وإيه اللي مابيقللوش؟
  4. إزاي Gateway بيلاقي MCP traffic حتى لو الـ URL مافيهوش mcp؟
  5. إيه الحاجات في المقال اللي هي وصف تجربة، وإيه اللي هو تسويق لمنتج؟
