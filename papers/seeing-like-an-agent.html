Week 1 reading

المقال ده من الـ readings بتاعة Week 1 في CS146S (Fall 2026) [cs146s2026]، فهو بيتقرا جنب محاضرة The Anatomy of a Modern Coding Agent. المحاضرة بتوريك الـ harness من برا، والمقال بيوريك إزاي الفريق اللي بناه بياخد قرارات الأدوات.

In one paragraph ​

الكاتب بيقول إن من أصعب حاجات بناء agent harness إنك تبني الـ action space بتاعه: الأدوات اللي الموديل بيعمل بيها حاجات في الدنيا [shihipar2026, intro]. والمقال مش بيدي قواعد ثابتة. بيدي طريقة تفكير: ادّي الموديل أدوات "shaped to its own abilities"، والطريقة الوحيدة إنك تعرف القدرات دي إنك تراقبه، وتقرا الـ outputs بتاعته، وتجرب. ده معنى "see like an agent" [shihipar2026, intro]. وبعدين بيحكي أربع تجارب من بناء Claude Code: أداة AskUserQuestion، والانتقال من TodoWrite لـ Tasks، والانتقال من RAG لـ Grep، والـ Claude Code Guide subagent.

About the source ​

  • الكاتب: Thariq Shihipar (@trq212)، وكان في فريق Claude Code في Anthropic وقت ما كتب المقال ("lessons we've learned ... while building Claude Code"). اتنشر كـ X article يوم 2026-02-27 [shihipar2026].
  • النوع: مقال خبرة عملية، مش paper. مفيهوش أرقام ولا benchmarks. كل الدروس جاية من ملاحظات الفريق وهو بيبني المنتج، والفرق بين اللي اتلاحظ واللي اتثبت موضح في Claims versus evidence.
  • علاقته بالكورس: الـ reading ده متحط في Week 1 [cs146s2026]. ورسالته قريبة جدًا من مبدأ الـ simplicity اللي المحاضرة التانية خلصت بيه (10. The principle: simplicity).

Key lessons ​

1. The framing: tools shaped to the model ​

الكاتب بيبدأ بسؤال: لو حد إداك مسألة رياضيات صعبة، تحب يكون معاك إيه؟ الورقة أقل حاجة، بس هتتعب في الحسابات اليدوي. الآلة الحاسبة أحسن، بس لازم تعرف تستخدم الـ options المتقدمة فيها. والكمبيوتر أسرع وأقوى حاجة، بس لازم تعرف تكتب كود وتشغله [shihipar2026, intro]. يعني الأداة الصح بتعتمد على مهارات اللي هيستخدمها، مش على قوة الأداة لوحدها.

ونفس السؤال في تصميم الـ agent: تدّيله أداة واحدة عامة زي bash أو code execution؟ ولا 50 أداة، واحدة لكل use case؟ [shihipar2026, intro]. المقال مش بيجاوب برقم. بيقول: راقب الموديل، وصمّم على أساس اللي بتشوفه منه فعلًا.

2. Elicitation: three attempts at AskUserQuestion ​

الهدف كان تحسين قدرة Claude إنه يسأل المستخدم (ده اللي بيتسمى elicitation). Claude كان يقدر يسأل بنص عادي، بس الإجابة على الأسئلة دي كانت بتاخد وقت أكتر من اللازم. فالسؤال بقى: إزاي نقلل الـ friction ونزوّد الـ bandwidth بين المستخدم وClaude؟ [shihipar2026, Improving Elicitation]

AttemptWhat they triedResult
1. Edit ExitPlanToolparameter جديد فيه array أسئلة جنب الخطةأسهل حل يتنفذ، بس لخبط Claude: بنطلب خطة وأسئلة عن نفس الخطة في وقت واحد. طب لو الإجابات عارضت الخطة؟ هيندَه الأداة مرتين؟ [shihipar2026, Attempt #1]
2. Change the output formatصيغة markdown معدّلة، مثلًا أسئلة في bullets والبدائل بين أقواس، والـ harness يعملها parse ويحوّلها UIأعم حل، وClaude كان كويس فيها نسبيًا، بس مفيش ضمان: ساعات يزوّد جمل، أو ينسى options، أو يغيّر الصيغة خالص [shihipar2026, Attempt #2]
3. AskUserQuestion toolأداة مستقلة Claude يقدر يندهها في أي وقت، والـ prompt بيشجّعه عليها بالذات في plan modeلما تتنده، الـ harness بيعرض modal بالأسئلة ويوقّف الـ loop لحد ما المستخدم يجاوب [shihipar2026, Attempt #3]

ليه التالتة اشتغلت؟ المقال بيقول [shihipar2026, Attempt #3]:

  • بتخلي الـ prompt يطلب structured output، وبتضمن إن المستخدم يشوف أكتر من option.
  • المستخدمين يقدروا يركّبوا عليها: يندهوها من الـ Agent SDK، أو يشيروا لها جوه skills.
  • والأهم: "Claude seemed to like calling this tool"، والـ outputs بتاعتها كانت كويسة. وهنا الجملة اللي بتلخص المقال: حتى أحسن أداة متصممة مش هتنفع لو Claude مش فاهم يندهها إزاي.

والكاتب نفسه مش متأكد إن ده الشكل النهائي للـ elicitation، لأن اللي بينفع مع موديل ممكن مايبقاش الأحسن مع موديل تاني [shihipar2026, Attempt #3].

شكل الأداة النهارده في الـ docs: الـ input فيه array اسمه questions، وكل سؤال فيه question، وheader (12 حرف بالكتير)، وoptions من 2 لـ 4 كل واحد فيه label وdescription، وmultiSelect. كل call فيه من 1 لـ 4 أسئلة، والإجابة بترجع في answers اللي بيربط نص كل سؤال بالـ label اللي اتختار [sdk-user-input]. والمستخدم يقدر يكتب إجابته بنفسه من خانة Other [claude-code-tools]. المثال ده توضيحي بنفس الشكل:

json
{
  "questions": [
    {
      "question": "Which database should the new service use?",
      "header": "Database",
      "options": [
        { "label": "PostgreSQL", "description": "Relational, already used by the API" },
        { "label": "SQLite", "description": "Single file, simplest to start" }
      ],
      "multiSelect": false
    }
  ]
}

3. Todos to Tasks: when a better model outgrows a tool ​

لما Claude Code نزل، الفريق لاحظ إن الموديل محتاج Todo list عشان يفضل ماشي على الخطة. فادّوه أداة TodoWrite بتكتب الـ todos أو تحدّثها وتعرضها للمستخدم. ومع كده كان بينسى، فضافوا system reminders كل 5 turns تفكّره بالهدف [shihipar2026, Tasks & Todos].

بعدين الموديلات اتحسنت، والموقف اتقلب: مابقتش محتاجة حد يفكّرها، وكمان بقت تلاقي الـ list نفسها قيد. الـ reminders خلّت Claude يفتكر إنه لازم يلتزم بالـ list بدل ما يعدّلها. وفي نفس الوقت Opus 4.5 بقى أحسن بكتير في استخدام الـ subagents، فظهر سؤال: الـ subagents هينسقوا مع بعض إزاي على Todo list واحدة؟ [shihipar2026, Tasks & Todos]

فالفريق شال TodoWrite وحط مكانه الـ Task tool [shihipar2026, Tasks & Todos]:

TodoWriteTasks
Purposeيخلي الموديل ماشي على الخطةيخلي الـ agents يتواصلوا مع بعض
Structurelist بسيطة بتتشطبفيها dependencies
Who uses itالموديل الرئيسيبتتشارك تحديثاتها بين الـ subagents
Changesبتتكتب في الأول وتتشطبالموديل يقدر يعدّلها ويمسحها

والدرس: كل ما قدرات الموديل تزيد، الأدوات اللي كان محتاجها زمان ممكن تبقى بتقيّده دلوقتي، فلازم ترجع لافتراضاتك باستمرار. وعشان كده الكاتب بيقول إن من المفيد تدعم مجموعة صغيرة من الموديلات قدراتها متقاربة [shihipar2026, Tasks & Todos]. القصة دي كمّلت بعد المقال كمان (شوف What changed since the article).

4. Search: from a vector index to Grep ​

أهم مجموعة أدوات عند Claude، حسب الكاتب، هي أدوات البحث اللي بيبني بيها الـ context بتاعه [shihipar2026, Designing a Search Interface]. أول ما Claude Code نزل، كان بيستخدم RAG vector database عشان يلاقي context لـ Claude. الـ RAG كان قوي وسريع، بس محتاج indexing وsetup، وممكن يبقى fragile في بيئات مختلفة كتير. والأهم: Claude كان بيتدّى الـ context بدل ما يلاقيه بنفسه [shihipar2026, Designing a Search Interface].

الفكرة اللي غيّرت ده بسيطة: لو Claude بيعرف يدوّر على الـ web، ليه مايدوّرش في الـ codebase؟ فادّوه Grep tool يدوّر بيه على الملفات ويبني الـ context بنفسه. والكاتب بيقول إن ده pattern بيشوفوه: كل ما Claude بيبقى أذكى، بيبقى أشطر في بناء الـ context بتاعه لو اتدّى الأدوات الصح [shihipar2026, Designing a Search Interface].

الفرق مش في نوع البحث بس (semantic مقابل keyword). الفرق في مين بيقرر إيه اللي يدخل الـ context: الـ retriever مرة واحدة قبل الشغل، ولا الموديل خطوة بخطوة وهو بيشتغل.

My reading: المقال بيتكلم عن البحث جوه codebase في coding agent، وماقالش إن RAG وحش بشكل عام. الكود مليان أسماء ثابتة (functions، classes، paths) بتخلي الـ keyword search قوي جدًا، وده ممكن مايبقاش صحيح بنفس الدرجة في نوع نصوص تاني.

5. Progressive disclosure and the Claude Code Guide subagent ​

لما Anthropic عملت Agent Skills، الفريق عمل formalize لفكرة الـ progressive disclosure: الـ agent بيكتشف الـ context المهم تدريجيًا عن طريق الاستكشاف. Claude بيقرا ملف skill، والملف ده ممكن يشير لملفات تانية Claude يقراها، وهكذا بشكل recursive. ومن أشهر استخدامات الـ skills إنها تزوّد Claude قدرات بحث، زي تعليمات استخدام API أو عمل query على database [shihipar2026, Designing a Search Interface].

والكاتب بيقول إن Claude، في خلال سنة، انتقل من إنه مش قادر تقريبًا يبني الـ context بتاعه، لإنه يعمل nested search في كذا طبقة ملفات عشان يوصل للـ context اللي محتاجه بالظبط. وإن الـ progressive disclosure بقت طريقتهم المعتادة لإضافة functionality من غير ما يضيفوا أداة[shihipar2026, Designing a Search Interface]. إزاي الـ skill بيظهر منها metadata بس في الأول والتفاصيل بتتحمل وقت الحاجة متشرح في المحاضرة التانية.

The Claude Code Guide agent. Claude Code وقت المقال كان فيه حوالي 20 أداة، والفريق بيسأل نفسه باستمرار هل محتاجينهم كلهم. والـ bar لإضافة أداة جديدة عالي، لأن كل أداة بتدّي الموديل "one more option to think about" [shihipar2026, Claude Code Guide Agent].

المشكلة كانت إن Claude مش عارف كفاية عن استخدام Claude Code نفسه: لو سألته تضيف MCP server إزاي، أو slash command معين بيعمل إيه، مايعرفش يرد. والفريق جرّب تلات حلول [shihipar2026, Claude Code Guide Agent]:

  1. يحطوا كل المعلومات دي في الـ system prompt. ماعملوهاش: المستخدمين نادرًا ما بيسألوا الأسئلة دي، فده كان هيزوّد context rot ويتداخل مع الشغل الأساسي لـ Claude Code: كتابة الكود.
  2. progressive disclosure بسيط: يدّوا Claude لينك للـ docs يحمّلها ويدوّر فيها. اشتغل، بس Claude كان بيحمّل نتايج كتير في الـ context عشان يوصل لإجابة، والمستخدم كان محتاج الإجابة بس.
  3. Claude Code Guide subagent: Claude متوجّه في الـ prompt إنه يندهه لما تسأل عن Claude Code نفسه، والـ subagent عنده تعليمات مفصلة إزاي يدوّر في الـ docs كويس وإيه اللي يرجّعه.

الكاتب بيعترف إن الحل مش perfect، وإن Claude لسه ممكن يتلخبط في أسئلة الـ setup، بس إنه أحسن بكتير من الأول. والنقطة المهمة: ضافوا حاجة للـ action space بتاع Claude من غير ما يضيفوا أداة[shihipar2026, Claude Code Guide Agent]. ده ممكن لأن الـ subagent بيتنده بأداة موجودة أصلًا: أداة Agent اللي بتشغّل subagent بـ context window خاص بيه [claude-code-tools]. فكل نتايج البحث بتفضل في الـ context بتاع الـ subagent، واللي بيرجع للـ agent الرئيسي هو الإجابة بس (نفس فكرة Subagents في المحاضرة التانية). والـ docs النهارده بتذكر claude-code-guide كـ helper agent built-in بيشتغل على Haiku، وClaude بيستخدمه لما تسأل عن features بتاعة Claude Code [claude-code-subagents].

6. An art, not a science ​

لو كنت مستني قواعد ثابتة لتصميم الأدوات، المقال بيقول صراحة إنه مش كده: تصميم الأدوات "as much an art as it is a science"، وبيعتمد جامد على الموديل اللي بتستخدمه، وهدف الـ agent، والبيئة اللي شغال فيها. ونصيحته الأخيرة: جرّب كتير، اقرا الـ outputs بتاعتك، جرّب حاجات جديدة. See like an agent [shihipar2026, An Art, not a Science].

Technical example ​

Attempt #2 هي نفس مشكلة الـ text protocol اللي في المحاضرة الأولى: لما الـ harness يعتمد إن الموديل يكتب صيغة نصية بالظبط، أي انحراف صغير بيكسر الـ parser. الـ parser بتاع الـ lab (extract_tool_invocations في mini_agent.py) بيقبل السطر ده:

text
tool: read_file({"filename": "main.py"})

بس الحالتين دول اتجربوا عليه (Python 3.12) ورجّعوا []، من غير أي error:

text
Tool: read_file({"filename": "main.py"})
tool: read_file(filename="main.py")

الأولى عشان T كبيرة والـ regex بيدوّر على tool: بالظبط. والتانية عشان filename="main.py" مش JSON، فـ json.loads بيفشل والسطر بيتعدّى بصمت. وده نفس نوع الأخطاء اللي المقال وصفه في Attempt #2: جملة زيادة، أو option ناقصة، أو صيغة مختلفة.

الحل في الحالتين واحد: خلّي الـ interaction بيانات مش نص. في الـ native tool calling الـ API بيرجّع اسم الأداة والـ arguments كـ fields جاهزة (Text protocol vs native tool calling). وفي AskUserQuestion الإجابة بترجع answers جاهزة، مش نص حر محتاج تفهمه:

python
# Attempt #2 style: the harness must find the question inside free text.
reply = "I recommend PostgreSQL.\n\nWould you prefer PostgreSQL or SQLite?"
# A parser that expects "- question [option / option]" finds nothing here.

# Attempt #3 style: the answer comes back as data (shape from the Agent SDK docs).
result = {"answers": {"Which database should the new service use?": "PostgreSQL"}}
choice = result["answers"]["Which database should the new service use?"]

Structured is not the same as correct

الـ structure بيحل مشكلة الشكل بس. لسه لازم تتحقق من الـ arguments قبل ما تنفذ أي أداة، زي ما صفحة Tool Calling بتوضح. ومعنى إن الإجابة جت في الشكل الصح مش معناه إنها صح.

What changed since the article ​

المقال اتكتب في فبراير 2026. الـ docs الحالية بتوري إن نفس الدروس فضلت تشتغل بعده:

  • Tasks: الـ Task tools (TaskCreate، TaskGet، TaskList، TaskUpdate) هي الـ default، و TodoWrite بقى disabled by default. بس كمان من v2.1.268 أدوات تتبع المهام دي كلها شغالة by default على Opus 4.7 وSonnet 4.6 وHaiku 4.5 والموديلات الأقدم بس. على الموديلات الأحدث بتتشال إلا لو فعّلتها، لأن "Claude keeps track of multi-step work without a written checklist"، وتعريفات الأدوات والـ reminders بتاكل context [claude-code-tools]. يعني نفس درس القسم 3 اتكرر مرة تانية.
  • Grep: على macOS وLinux وWSL، أدوات Glob وGrep المستقلة مش في الـ default tool set، وClaude بيدوّر بـ find وgrep من خلال أداة Bash (نسخ embedded من bfs وugrep). على Windows الاتنين موجودين by default [claude-code-tools]. My reading: الفكرة الأساسية (الموديل هو اللي بيدوّر) زي ما هي؛ اللي اتغيّر إن البحث بقى جوه أداة عامة موجودة أصلًا.
  • Tool count: المقال قال حوالي 20 أداة في فبراير [shihipar2026, Claude Code Guide Agent]، والمحاضر قال حوالي 40 في سبتمبر [cs146s-0924, 25:58]، وجدول الـ docs النهارده فيه أكتر من 40 اسم، كتير منهم مش شغال by default أو مرتبط بنظام تشغيل أو موديل معين [claude-code-tools]. الرقم بيتغير مع الإصدار وطريقة العد، فالمهم الفكرة: كل أداة ليها تمن.
  • AskUserQuestion: السؤال بيفضل مفتوح لحد ما تجاوب، إلا لو ظبطت askUserQuestionTimeout[claude-code-tools]. وفي الـ Agent SDK الأداة مش متاحة جوه الـ subagents [sdk-user-input].

Notes versus source ​

الـ study notes (مكتوبة بمساعدة AI) كانت قريبة من المقال في أغلبها، مع التصحيحات دي:

  • قالت إن "5 أدوات بس ممكن تحقق نتايج أحسن من 50". ده مش في المقال؛ الـ 50 أداة جت كسؤال افتراضي بس.
  • قالت إن الـ AskUserQuestion اتختارت "لأنها قدّمت نتايج عملية أحسن". المقال بيقول السبب الأهم إن Claude كان بيحب يندهها والـ outputs كانت كويسة، ومعاهم الـ structured output والـ composability.
  • قدّمت الـ progressive disclosure كحل لمشكلة إن الـ 50 tool schema بياكلوا context. المقال بيقدمها كطريقة يضيف بيها functionality من غير ما يضيف أداة، وتمن الأداة عنده إنها "one more option to think about"؛ الـ context rot ظهر في مثال الـ system prompt بس.
  • ماذكرتش: إن الكاتب Thariq Shihipar، وحوالي 20 أداة، وOpus 4.5 والـ subagents، ونصيحة دعم موديلات قدراتها متقاربة، وإن الحلول مش perfect، وقسم "An Art, not a Science".
  • الأمثلة اللي في الـ notes (analyze-tender، الـ JSON بتاع {"question", "options"}، الـ hybrid retrieval) أمثلة من الـ notes نفسها، مش من المقال، والصفحة دي ماستخدمتهاش. شكل الـ JSON الحقيقي للأداة فوق من الـ docs.

Limitations and open questions ​

Stated by the author:

  • الـ AskUserQuestion ممكن مايكونش الشكل النهائي، لأن اللي بينفع مع موديل ممكن مايبقاش الأحسن مع تاني [shihipar2026, Attempt #3].
  • الـ Claude Code Guide subagent مش perfect، وClaude لسه بيتلخبط أحيانًا في أسئلة الـ setup [shihipar2026, Claude Code Guide Agent].
  • مفيش قواعد ثابتة؛ كله بيعتمد على الموديل والهدف والبيئة [shihipar2026, An Art, not a Science].

Open questions:

  • المقال كله عن موديلات Claude جوه Claude Code. هل نفس القرارات تنفع مع موديلات تانية؟ الكاتب نفسه بيقول إن الأدوات مرتبطة بالموديل.
  • إزاي تقيس إن الموديل "بيحب" أداة؟ المقال مابيوصفش طريقة؛ سؤال عملي للي بيبني harness.
  • إمتى الـ reminder يبطّل يساعد ويبدأ يقيّد؟ المقال بيقول إن ده حصل، بس مابيقولش اكتشفوه إزاي.

Exercises ​

Exercise: Tool, skill, subagent, or nothing?

لكل حاجة من دول، اختار: أداة جديدة، skill (progressive disclosure)، subagent، ولا ماتضيفش حاجة. (1) الـ agent محتاج يسأل المستخدم سؤال اختيار من متعدد ويستنى الإجابة. (2) الـ agent محتاج يعرف إزاي يعمل query على database داخلي ليه syntax خاص. (3) المستخدمين ساعات بيسألوا عن إعدادات الأداة نفسها. (4) موديل جديد بقى بيلتزم بخطته من غير أي تذكير.

Solution

(1) أداة: محتاج structured output وسلوك خاص في الـ harness (يوقّف الـ loop)، زي AskUserQuestion. (2) skill: تعليمات بتتحمل وقت الحاجة، وده من الاستخدامات اللي المقال ذكرها للـ skills. (3) subagent: زي الـ Claude Code Guide، عشان نتايج البحث في الـ docs ماتملاش الـ context الرئيسي. (4) ولا حاجة، وغالبًا تشيل الـ reminder القديم: ده درس TodoWrite.

Exercise: Break the format

الـ harness بيطلب من الموديل يكتب أسئلته كده: - question [option / option / option]. اكتب تلات ردود ممكن تكسر الـ parser، بنفس أنواع الأخطاء اللي المقال ذكرها، وبعدين اقترح schema بديلة.

Solution

(1) جملة زيادة قبل السؤال أو بعده ("I recommend PostgreSQL."). (2) option ناقصة أو أقواس من غير بدائل. (3) صيغة مختلفة خالص ("Would you prefer PostgreSQL or SQLite?"). البديل: أداة input بتاعها questions فيها question وoptions (كل option ليها label)، والإجابة ترجع answers، زي شكل AskUserQuestion في الـ docs.

Exercise: Design the experiment

الـ harness بتاعك بيحقن reminder كل 5 turns بالخطة. وصف تجربة بسيطة تعرف منها الـ reminder ده لسه بيساعد ولا بقى بيقيّد الموديل.

Solution

شغّل نفس مجموعة المهام مرتين (بالـ reminder ومن غيره)، ويكون فيها مهام بتظهر فيها معلومة جديدة في النص بتخلي الخطة الأصلية غلط. قارن نسبة نجاح المهام، وهل الموديل عدّل الخطة لما ظهرت المعلومة، وعدد الـ tokens. لو الـ reminder بيخلي الموديل يكمّل على الخطة القديمة، ده نفس اللي المقال وصفه. (المقال نفسه مانشرش تجربة زي دي؛ ده تصميم مقترح.)
