AGENTS.md (Factory documentation) ​

ReviewedPublishedAI-assisted

Factory's guide to AGENTS.md for its Droid agent: commands first, rules that can be checked, nested files only for real differences, a stated discovery and precedence model, compatible filenames that should not all be created, and character caps that are ceilings, not targets.

In one paragraph ​

ده مش مقال رأي، ده توثيق منتج: إزاي Droid (الـ coding agent بتاع Factory) بيقرا AGENTS.md. قيمته إنه بيحوّل نصايح عامة لقواعد محددة: الأوامر الأول، وكل قاعدة لازم تبقى حاجة تقدر تقول "اتعملت ولا لأ"، وnested files بس للاختلاف الحقيقي، ونموذج واضح لمين يكسب لو التعليمات اتعارضت، وحدود حجم بالأرقام.

Learning objectives ​

  • تكتب AGENTS.md قواعده قابلة للتحقق.
  • تشرح نموذج Factory للـ discovery والـ precedence، وتقارنه بـ Claude Code.
  • تعرف إمتى nested file يستاهل، وإيه اللي مايتحطش في الملف خالص.

Problem ​

الـ agent محتاج "project briefing" قبل ما يكتب كود: إزاي يثبّت، يشغّل، يختبر، يعدّل، يتحقق، ويفضل جوه حدود الـ repo. والمطلوب يبقى "short, specific, and easy to verify" [factory-agentsmd, intro].

Method ​

Commands first, then rules you can check ​

خطوات البداية: ملف واحد في الـ root؛ الأوامر بالظبط (install، dev، test، typecheck، lint، build) مع الـ flags لو الأمر الكامل غالي؛ بعدين الـ layout والـ generated files والأمان وإثبات الانتهاء؛ وcommit مع المشروع [factory-agentsmd, Create your first AGENTS.md]. والأقسام المقترحة: overview، commands، repository map، conventions، testing rules، generated files، security rules، PR expectations [factory-agentsmd, What to include].

الفرق بين قاعدة تتحقق منها وقاعدة لأ [factory-agentsmd, What to include]:

markdown
## Testing
- Run `pnpm test -- path/to/file.test.ts` for focused changes.
- Run `pnpm test` before completing broad refactors.
- Add a regression test for every bug fix when practical.

مقابل "Be careful." و"Make sure everything works.": كلام مايتحاسبش عليه.

The narrowest durable surface ​

Factory عندها أسطح مختلفة: AGENTS.md للتعليمات الدايمة، وDESIGN.md لإرشادات التصميم، وSKILL.md للـ workflows اللي تتحمّل وقت الحاجة، و.factory/commands/* للـ slash commands، و.factory/settings.json للإعدادات [factory-agentsmd, instruction surface]. ونفس قاعدة Anthropic: الـ runbook الطويل مكانه skill أو link، مش AGENTS.md.

Discovery and precedence ​

Droid بيدوّر من الـ working directory لحد الـ git root، وفي كل مستوى في .factory/ و.agents/ و.agent/، وكمان في نظايرهم في الـ home. ولو أكتر من ملف انطبق [factory-agentsmd, Discovery and precedence]:

  1. طلب المستخدم الحالي أولى من التعليمات الدايمة.
  2. الـ nested files بتدقّق الـ root لفولدر معيّن.
  3. ملفات المشروع أولى من الـ personal defaults.
  4. الملفات الشخصية تبقى تفضيلات، مش متطلبات بتعارض قواعد الـ repo.

وفيه تفصيلة بتفرق [factory-agentsmd, Nested instructions]: القراءة والتعديل والـ listing والبحث في فولدر بيشغّلوا الـ discovery؛ أوامر الـ shell اللي بتعدّي على Execute لأ. يعني cat apps/web/x.ts من الـ shell مش هيحمّل apps/web/AGENTS.md.

Compatible filenames are not a checklist ​

Droid بيقرا AGENTS.md وagents.md وAgents.md وCLAUDE.md وClaude.md، بس "This is a compatibility set, not a setup checklist. Do not create every file" [factory-agentsmd, Compatible filenames].

والعكس في Claude Code مختلف: by default بيقرا AGENTS.md بس لو مفيش CLAUDE.md (أو CLAUDE.local.md) في الـ working directory أو فوقه، وده محتاج v2.1.277 أو أحدث؛ وفيه setting تخليه يقرا الاتنين [cc-memory, AGENTS.md]. يعني نفس الـ repo ممكن يتقري بشكل مختلف حسب الأداة.

"These are caps, not targets. Smaller files are usually better" [factory-agentsmd, Context budget].

What to keep out ​

secrets وcredentials وhost names خاصة؛ نسخ كاملة من docs موجودة؛ inventories للفولدرات هتبقى قديمة؛ تفضيلات شخصية ضد المشروع؛ notes مؤقتة لمهمة؛ وتعليمات بتلغي الـ validation من غير سبب ضيق وصريح [factory-agentsmd, What to avoid].

Technical example ​

script صغير (من عندي) بيطبّق فكرة "rules you can check": بيعلّم السطور اللي مفيهاش أمر أو path أو رقم.

python
import re
import sys
from pathlib import Path

CHECKABLE = re.compile(r"`[^`]+`|\b\d+\b|\b(run|add|do not|never|before|after)\b", re.IGNORECASE)

for n, line in enumerate(Path(sys.argv[1]).read_text(encoding="utf-8").splitlines(), start=1):
    rule = line.strip()
    if rule.startswith("- ") and not CHECKABLE.search(rule):
        print(f"line {n}: vague rule: {rule[2:]}")

على السطرين "Be careful." و"Make sure everything works." بيطلع الاتنين؛ وعلى أمثلة Factory الـ concrete مابيطلعش حاجة. heuristic، مش حكم: "Prefer composition over inheritance" هتتعلّم vague وهي قاعدة معقولة.

Limitations ​

  • Stated by the authors: النموذج بتاع الـ precedence "mental model" لـ Droid، مش مواصفة [factory-agentsmd, Discovery and precedence].
  • My assessment: ده سلوك Factory في تاريخ الوصول، ومش بالضرورة لأي agent تاني (Claude Code مثلًا بيعامل AGENTS.md بشكل مختلف). ولو فيه security policy من مستوى أعلى (managed settings)، ماتفترضش إن طلب المستخدم يقدر يتخطاها.

Exercises ​

Exercise: Make it checkable

حوّل التلات قواعد دول لقواعد تتحقق منها: (1) "Write good tests." (2) "Don't break the API." (3) "Be careful with generated code."

Solution

مثلًا: (1) "Add a regression test for every reproducible bug; run pnpm test -- <file> after the change." (2) "Run pnpm test:contract before finishing any change under api/." (3) "Do not edit generated/ by hand; run pnpm codegen instead." كل واحدة فيها فعل وأمر أو path تقدر تقول اتعمل ولا لأ [factory-agentsmd, What to include].

Exercise: Two agents, one repo

repo فيه CLAUDE.md وAGENTS.md بمحتوى مختلف. إيه اللي Droid بيقراه، وإيه اللي Claude Code بيقراه by default؟

Solution

Droid بيقرا الاتنين كـ compatible filenames (والتكرار بيضيّع context). Claude Code by default بيقرا CLAUDE.md بس لأنه موجود، إلا لو غيّرت الـ Project instructions setting [factory-agentsmd, Compatible filenames] [cc-memory, AGENTS.md]. الحل الأنضف: ملف واحد، والتاني import أو symlink.

Review questions ​

  1. ليه "commands first"؟
  2. إيه اللي بيشغّل الـ nested discovery في Droid وإيه اللي مابيشغّلوش؟
  3. ليه إن Droid بيدعم 5 أسماء ملفات مش سبب تعمل الخمسة؟
  4. إيه معنى إن الـ 80,000 حرف "cap, not target"؟
