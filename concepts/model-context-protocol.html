Model Context Protocol (MCP) ​

ReviewedPublishedAI-assisted

An open protocol, built on JSON-RPC, through which AI applications (hosts) connect to servers that expose tools, resources, and prompts, so one integration per side replaces a custom connector per pair.

Also known as
MCP, MCP server, MCP client

2026-11-07

Definition ​

Definition: Model Context Protocol

الـ MCP بروتوكول مفتوح بيخلّي أي AI application يوصل لأي نظام خارجي بطريقة موحدة. الـ application (الـ host) بيكلم servers، وكل server بيعرض tools وresources وprompts بصيغة ثابتة مبنية على JSON-RPC [mcp-spec]. بالبلدي زي ما المحاضرة قالت: "standard format for exposing tools to LLMs" [cs146s-1001].

Learning objectives ​

  • تشرح المشكلة اللي MCP بيحلها بمعادلة M×N→M+N.
  • تفرّق بين الـ host والـ client والـ server والـ tool.
  • تمشي على دورة tool call كاملة: tools/list ثم tools/call.
  • تعرف إيه اللي MCP مش بيحله: الأمان والصلاحيات والـ context bloat.

Intuition ​

قبل الـ USB، كل جهاز كان ليه فيشة شكل. لو عندك 3 أجهزة كمبيوتر و3 طابعات بأشكال مختلفة، محتاج 9 كابلات. الـ USB خلّى كل كمبيوتر يعمل port واحد، وكل طابعة تعمل فيشة واحدة. MCP بيعمل ده بين الـ AI applications والأنظمة.

التشبيه بيبوظ عند نقطة: الـ USB ميكانيكي، بينما MCP بيوصف أدوات للموديل، والموديل لازم يفهم الوصف ويختار صح. فجودة الوصف بتفرق، وده موضوع تصميم الـ servers في MCP, Tool Calling, and Beyond.

Formal explanation ​

From M × N to M + N ​

لو عندك M applications وN خدمات، من غير بروتوكول مشترك محتاج لحد M×N connector. مع MCP، كل application بيطبّق client مرة، وكل خدمة بتعمل server مرة: M+N [cs146s-1001]. والمحاضر ضاف إنك مش بتعيد كتابة الحاجات المشتركة بين الـ connectors، زي الـ authentication والـ error handling والـ rate limiting، في كل مرة [cs146s-1001].

Roles ​

RoleWhat it isExample
Hostالـ application اللي المستخدم بيتعامل معاه؛ بينسق كل حاجة وبيطبّق حدود الأمانClaude Code، Cursor، Claude Desktop
Clientجزء جوه الـ host؛ كل client بيكلم server واحد بس (1:1)client لكل server متوصل
Serverwrapper صغير قدام أداة أو مصدر بياناتGitHub server، filesystem server
Toolfunction الموديل يقدر يطلبها، ليها name وdescription وinputSchemasearch_tickets(query)

ده كله من الـ spec [mcp-spec]، والمحاضرة بتوصف نفس التقسيم [cs146s-1001]. والـ servers بتعرض تلات أنواع primitives: tools وresources وprompts [mcp-spec].

نقطة أمان مهمة من الـ spec: الـ conversation history كاملة بتفضل عند الـ host، والـ host هو اللي بيتحكم في أي تفاعل بين servers [mcp-spec]. يعني الـ server مابيشوفش المحادثة، بيشوف الـ tool call اللي اتبعتله بس.

One tool call, end to end ​

  1. Discovery: الـ client بيبعت tools/list، والـ server بيرجّع لكل أداة اسمها ووصفها والـ inputSchema (JSON Schema) [mcp-spec].
  2. الـ host بيحط التعريفات دي في الـ context بتاع الموديل مع طلب المستخدم [cs146s-1001].
  3. الموديل بيطلع tool call منظم، والـ host بيبعته للـ server بـ tools/call [mcp-spec].
  4. الـ server بينفذ ويرجّع النتيجة، والمحادثة بتكمّل [cs146s-1001].

لاحظ إنها نفس فكرة الـ tool registry في Tool Calling، بس الأدوات بقت برا برنامجك، ووصفها بييجي من الـ server وقت التشغيل.

Transports ​

الـ spec فيها transportين standard: stdio (الـ server process محلي، والكلام على الـ standard input/output) وStreamable HTTP للـ servers البعيدة. الـ transport القديم HTTP+SSE deprecated من إصدار 2025-03-26 [mcp-spec]. وفي المحاضرة: الـ server اللي بتبنيه بنفسك غالبًا محلي على stdio، وخدمات زي Gmail غالبًا remote على HTTP [cs146s-1001].

The spec moved after the lecture's slide

الـ slide بتقول إن الـ client بيحتفظ بـ "stateful session per server" [cs146s-1001]. إصدار الـ spec الحالي (2026-07-28) غيّر ده: "MCP is a stateless protocol"، واتشال الـ initialize handshake، وكل request بقى شايل الـ protocol version والـ capabilities بتاعته [mcp-spec]. الفكرة الأساسية (client لكل server، وdiscovery، وtool calls) زي ما هي.

Technical example ​

تعريف أداة بالشكل اللي بيرجع من tools/list (مثال توضيحي):

json
{
  "name": "jira_search_tickets",
  "description": "Search Jira tickets with a free-text query. Returns at most `limit` tickets.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "query": {"type": "string", "description": "Words to search for in title and body"},
      "limit": {"type": "integer", "minimum": 1, "maximum": 50, "default": 10}
    },
    "required": ["query"]
  }
}

الاسم فيه prefix الخدمة (jira_) عشان الموديل يلاقيه ويفرّقه عن أدوات servers تانية، وده من نصايح المحاضرة ("name tools for discovery") [cs146s-1001].

Limitations and common misconceptions ​

  • "MCP replaces tools." لأ. MCP طريقة موحدة لتوفير tools، مش بديل ليها.
  • "MCP handles security." البروتوكول بيوحد طريقة الكلام، بس الصلاحيات، والتأكيد قبل العمليات الخطيرة، والـ audit logs لسه مسؤوليتك وعلى الـ host والـ server.
  • "More servers, smarter agent." كل أداة من كل server بتدخل الـ context. في الأيام الأولى، server GitHub لوحده كان بيدي حوالي 120 لـ 150 أداة، والمحاضر قال إن ده ماكانش نظام كويس [cs146s-1001].
  • "An MCP server is a REST API wrapper." المحاضر بيقول بوضوح لأ: الـ API معمولة للبشر، والـ mapping واحد لواحد بيضيع فرصة تصميم أدوات مناسبة للموديل [cs146s-1001].

Exercises ​

Exercise: Count connectors

فريق عنده 4 AI tools داخلية و7 أنظمة. كام connector محتاجين من غير MCP، وكام implementation مع MCP؟ وهل عدد الـ connections وقت التشغيل قل؟

Solution

من غير MCP: 4×7=28. مع MCP: 4+7=11. عدد الـ connections وقت التشغيل ماقلش بالضرورة (كل tool ممكن يتوصل بكل server)، اللي قل هو الكود المخصص اللي لازم يتكتب ويتصان.

Exercise: Read a tool definition like a model

بص على تعريف jira_search_tickets فوق. اكتب 3 أسئلة الموديل ممكن يحتار فيها لو الـ description كان "Search tickets" بس.

Solution

أمثلة: بيدوّر في العنوان بس ولا في المحتوى كمان؟ بيرجّع كام نتيجة؟ ده Jira ولا GitHub issues؟ كل سؤال من دول ممكن يخلي الموديل يختار الأداة الغلط أو يبعت arguments غلط.

Key takeaways

  • MCP بيحوّل M×N connector لـ M+N implementation.
  • Host فيه clients، وكل client بيكلم server واحد، والـ server بيعرض tools وresources وprompts.
  • الدورة: tools/list ثم tools/call، والتعريفات بتدخل الـ context بتاع الموديل.
  • MCP مش بيحل الأمان ولا الـ context bloat لوحده.

Review questions ​

  1. ليه المعادلة M×N→M+N مش معناها إن الـ connections قلت؟
  2. إيه الفرق بين الـ host والـ client؟
  3. الـ server بيشوف المحادثة كلها؟ وليه ده مهم؟
  4. إمتى تستخدم stdio وإمتى Streamable HTTP؟
