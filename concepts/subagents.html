Definition ​

Definition: Subagent

الـ subagent هو agent متخصص الـ agent الرئيسي بيوزّع عليه جزء من المهمة. بيشتغل في context window منفصلة بـ system prompt خاص بيه، وأدوات وصلاحيات خاصة بيه، ولما يخلص بيرجّع النتيجة للـ agent الرئيسي [cc-subagents]. الـ slides بتاعة CS146S بتلخصه في "runtime delegation": فصل نضيف بين الـ contexts بتاعة شغلانات مختلفة، ومن الـ subagent "only final message is returned" [cs146s-1013].

المشكلة اللي بيحلها هي الـ context. كل ملف الـ agent بيقراه وكل tool result بيرجع بيتضاف للمحادثة. لو محتاج معلومة صغيرة في الآخر، مش منطقي إن 15 ملف وعشرين search result يفضلوا في الـ context الرئيسي لحد آخر الـ session.

Learning objectives ​

  • تشرح المشكلة اللي الـ subagents بتحلها، وتمنها.
  • تعدّد اللي بيدخل الـ subagent في الأول، وتعرف إنه مابيشوفش تاريخ المحادثة.
  • تفرّق بين الـ built-in subagents في Claude Code، وتعرف إمتى تعمل custom واحد.
  • تفهم إن العزل في الـ context مش في الـ file system.
  • تختار بين subagent، وskill، وhook، وMCP، وCLAUDE.md لكل موقف.

Intuition ​

تخيل إنك مدير فريق، وعايز تعرف مين المسؤول عن الـ refunds في نظام دفع كبير. ممكن تقعد تقرا الملفات بنفسك. أو تقول لمهندس: "روح دوّر وارجعلي باسم الـ service والـ function". هو هيفتح ملفات ويعمل search ويتتبع calls، وفي الآخر يرجعلك بجملة: "RefundService.process_refund() في services/refunds.py".

إنت مش محتاج تشوف كل خطوة عملها، محتاج الخلاصة. ده دور الـ subagent بالظبط. بس خلي بالك من الوش التاني: لو المهندس لاحظ إن فيه legacy refund handler لسه شغال في حالات معينة وماقالكش، إنت مش هتعرف. اللي مادخلش في الخلاصة ضاع من وجهة نظرك.

Formal explanation ​

What a subagent receives ​

كل subagent (غير الـ fork، تحت) بيبدأ بـ context جديد ومعزول. مابيشوفش تاريخ محادثتك، ولا الـ skills اللي اتنادت، ولا الملفات اللي Claude قراها. Claude بيكتب رسالة مهمة بتلخص المطلوب، والـ subagent بيشتغل منها [cc-subagents]. اللي بيدخل في الأول [cc-subagents]:

InputWhat it is
System promptالـ prompt بتاع الـ subagent نفسه ومعاه تفاصيل البيئة، مش الـ system prompt بتاع Claude Code
Task messageرسالة التفويض اللي Claude بيكتبها
CLAUDE.md filesنفس الـ hierarchy اللي المحادثة الرئيسية بتحملها، ما عدا Explore وPlan
Git statussnapshot من الـ repo، ما عدا Explore وPlan
Preloaded skillsلو اتحددت في الـ skills field بتاع الـ subagent

يعني القرار اللي اتفقت عليه مع الـ agent الرئيسي من ساعة مش هيوصل للـ subagent، إلا لو اتكتب في رسالة المهمة أو كان مكتوب في ملف يقدر يلاقيه. والـ docs بتقول صراحة: لو قاعدة لازم توصل، زي "تجاهل vendor/"، اكتبها في الـ prompt وإنت بتفوّض [cc-subagents].

What comes back ​

الـ agent الرئيسي بيستلم الرسالة الأخيرة بس [cs146s-1013; segner2026]. الشغل الوسيط مابيدخلش المحادثة الرئيسية. بس ده مش معناه إنه "اتمسح": الـ transcripts بتاعة الـ subagents بتتحفظ في ملفات منفصلة، ومابتتأثرش بالـ compaction بتاعة المحادثة الرئيسية، وClaude يقدر يكمّل subagent خلص (general-purpose أو custom) بالـ SendMessage tool وهو فاكر كل اللي عمله [cc-subagents]. Explore وPlan بالذات one-shot ومابيتكملوش [cc-subagents].

Isolation is about context, not files ​

العزل هنا في الـ conversation context بس. لو الـ subagent عنده صلاحية يعدّل ملفات وعدّل، التعديلات موجودة على الـ disk [cc-subagents]. وكمان /rewind غالبًا مابيرجعش تعديلات الـ subagents، لأنها مش جوه الـ checkpoints بتاعة الـ session [cc-checkpointing]. لو عايز عزل للملفات كمان، فيه isolation: worktree بيدي الـ subagent نسخة منفصلة من الـ repo [cc-subagents].

وده نفس السبب اللي يخلي الأحسن إن مرحلة البحث بالتوازي تبقى read-only: لو كذا subagent بيعدّلوا نفس الملفات في نفس الوقت، هيحصل تعارض.

Built-in subagents in Claude Code ​

Claude Code فيه subagents جاهزة بيستخدمها لوحده لما تناسب المهمة [cc-subagents]:

SubagentToolsPurpose
Exploreread-only (Write وEdit ممنوعين)بحث سريع في الـ codebase وفهمه، بمستوى thoroughness (quick، medium، very thorough)
Planread-onlyبحث في الـ codebase أثناء plan mode قبل ما يقدّم خطة
general-purposeكل الأدوات المتاحة للـ subagentsمهام معقدة multi-step فيها بحث وتعديل

وفيه helpers تانية بتشتغل تلقائيًا، زي statusline-setup وclaude-code-guide [cc-subagents]. والـ built-in subagents بيورثوا permission rules بتاعة المحادثة الرئيسية [cc-subagents].

Custom subagents ​

لو بتطلب نفس نوع الشغل بنفس التعليمات كل شوية، اعمل custom subagent: ملف Markdown في .claude/agents/ (للمشروع) أو ~/.claude/agents/ (ليك في كل المشاريع). الـ frontmatter فيه الإعدادات، والـ body هو الـ system prompt [cc-subagents]. name وdescription بس هما المطلوبين، والـ description هو اللي Claude بيستخدمه عشان يقرر إمتى يفوّض [cc-subagents].

markdown
---
name: code-explorer
description: Read-only codebase exploration. Use to locate code and trace call paths.
tools: Read, Glob, Grep
---

You are a codebase exploration specialist.
- Trace the relevant functions and their callers.
- Return concise findings with file paths and line numbers.
- List edge cases, exceptions, and anything you are unsure about.
- Never modify files.

الـ descriptions دي بتتحمل في الـ context من أول الـ session، فخليها قصيرة، وحط التفاصيل في الـ system prompt اللي بيتحمل بس لما الـ subagent يشتغل [cc-subagents]. والـ slides بتقول نفس الفكرة: "name, description, tool list loaded at session start" [cs146s-1013].

The fork: a subagent that inherits the conversation ​

فيه نوع استثنائي: الـ fork بيورث المحادثة كلها لحد اللحظة دي (نفس الـ system prompt والأدوات والموديل والـ history)، فمش محتاج تعيد شرح الموقف. بس نتايج أدواته برضه مابتدخلش محادثتك، وبيرجع النتيجة الأخيرة بس [cc-subagents]. يعني بيتنازل عن عزل الـ input، ومحتفظ بعزل الـ output.

When to use one, and when not ​

الـ docs بتلخص الاختيار [cc-subagents]:

Use the main conversation whenUse a subagent when
المهمة فيها أخذ ورد كتير وتحسين متكررالمهمة بتطلّع output كتير مش محتاجه في الـ context الرئيسي
مراحل كتير بتشارك context كبير (تخطيط، تنفيذ، اختبار)عايز تفرض أدوات أو صلاحيات محددة
تغيير صغير ومحددالشغل مستقل ويقدر يرجّع ملخص
السرعة مهمة: الـ subagent بيبدأ من الصفر

والـ slides بتاعة CS146S بتدي أمثلة: استكشاف الـ codebase، وتبسيط الكود بعد تغيير، واختبار الـ app end-to-end، وبشكل عام "perfect for side tasks" [cs146s-1013]. والمراجعة المستقلة مثال كلاسيكي: شوف Agent Code Review.

The costs ​

  • Tokens: الـ subagent بيبعت requests خاصة بيه بتتحسب من نفس الـ usage limits [cc-subagents]. والـ slides في المحاضرة التانية قالت إن التوازي بيزوّد تكلفة الـ tokens [cs146s-0924].
  • Return volume: لو شغّلت subagents كتير كل واحد بيرجّع نتيجة طويلة، النتايج دي نفسها هتملا الـ context الرئيسي [cc-subagents].
  • Lost details: أكبر عيب عملي. اللي الـ subagent ماكتبوش في رسالته الأخيرة، الـ agent الرئيسي مايعرفوش. فللمهام المهمة اطلب شكل محدد للنتيجة: الخلاصة، ومسارات الملفات وأرقام السطور، والأدلة، والاستثناءات والـ edge cases، والحاجات اللي لسه مش متأكد منها.

Subagent, skill, hook, MCP, CLAUDE.md ​

دول مش بدايل لبعض، كل واحد بيحل مشكلة مختلفة، وتقدر تجمعهم:

MechanismWhat it doesExample
CLAUDE.mdتعليمات ثابتة بتتحمل كل session؛ الموديل بيحاول يلتزم بيها"المشروع بيستخدم FastAPI"
Skillإجراء متكرر بيتحمل لما يتطلب أو يناسب المهمةchecklist للـ code review
Subagentينفذ مهمة في context معزول ويرجّع النتيجةمراجع مستقل، أو استكشاف 200 ملف
Hookأمر بيتنفذ تلقائيًا عند event معين، مش بقرار الموديلformatter بعد كل Edit
MCPيوصّل الـ agent بأدوات وخدمات براGitHub، Jira، قاعدة بيانات

مقالة Anthropic اللي في قراءات الأسبوع الرابع بتلخص الفرق ده: الـ subagents للـ side tasks اللي الـ output الوسيط بتاعها مش هتحتاجه تاني، والـ hooks للسلوك اللي لازم يحصل كل مرة، والـ skills للإجراءات [segner2026]. الـ skill هو طريقة الشغل، والـ subagent هو اللي بينفذ في عزلة.

Diagram ​

الرسمة فوق بتوضح الحدود: اللي داخل (رسالة المهمة والـ system prompt)، واللي طالع (الرسالة الأخيرة بس)، واللي بيعدّي الحدود من غير ما تاخد بالك (تعديلات الملفات). شرح الفكرة في سياق الـ harness كله في The Anatomy of a Modern Coding Agent.

Limitations and common misconceptions ​

  • "The subagent knows what we discussed." لأ. بيعرف رسالة المهمة والـ system prompt بتاعه وملفات المشروع. الاستثناء هو الـ fork [cc-subagents].
  • "Subagents save tokens." بيوفروا في الـ context الرئيسي، مش في التكلفة الكلية. ممكن التكلفة تزيد [cc-subagents].
  • "The subagent's work is thrown away." من وجهة نظر الـ agent الرئيسي، أيوه، بيستلم الرسالة الأخيرة بس. بس الـ transcript متخزن، وممكن يتكمّل [cc-subagents].
  • "Isolated means safe." العزل في الـ context، مش في الملفات. حدد الأدوات والصلاحيات لكل subagent بعناية [cc-subagents].
  • "Every task deserves a subagent." سؤال بسيط عن syntax أو شرح function صغيرة مش محتاج subagent. التفويض ليه تمن: وقت بداية من الصفر، وتفاصيل ممكن تضيع.
  • الأسماء والتفاصيل (Explore، Plan، الـ frontmatter fields) خاصة بـ Claude Code وبتتغير مع الإصدارات.

Exercises ​

Exercise: Main agent or subagent

لكل موقف اختار: الـ agent الرئيسي، Explore، Plan، custom subagent، ولا كذا subagent بالتوازي؟ (1) شرح function فيها 10 سطور. (2) "دوّر على كل الأماكن اللي بتستخدم JWT_SECRET". (3) تحليل الـ auth design الحالي قبل إضافة OAuth، وإنت في plan mode. (4) مراجعة مستقلة للتغييرات بعد ما تخلص feature. (5) بحث منفصل في تلات modules مالهمش علاقة ببعض. (6) مهمة محتاجة كل القرارات اللي اتاخدت في الـ session.

Solution

(1) الـ agent الرئيسي. (2) Explore: بحث read-only. (3) Plan (أو custom subagent). (4) review subagent، زي /code-review. (5) كذا subagent بالتوازي، والأحسن read-only. (6) الـ agent الرئيسي، أو fork، أو subagent بس بعد ما تكتب القرارات المهمة في رسالة المهمة.

Exercise: Write a good return format

عندك subagent بيبحث عن مين بيعمل الـ refunds. اكتب الجزء من الـ system prompt اللي بيحدد شكل النتيجة، بحيث الـ agent الرئيسي مايفوتهوش legacy handler لو موجود.

Solution

مثال: "Return: (1) the main answer in one sentence; (2) file paths with line numbers; (3) the evidence for each claim; (4) every other code path that also handles refunds, including legacy or rarely used ones; (5) what you could not confirm." البند (4) هو اللي بيمنع الملخص يحذف الاستثناءات.

Exercise: Files versus context

subagent عنده Edit وعدّل 3 ملفات، وبعدين إنت عملت /rewind لنقطة قبل ما تفوّضه. الملفات رجعت؟

Solution

غالبًا لأ. تعديلات الـ subagent عادةً مش جوه الـ checkpoints، و/rewind بيرجّع بس الملفات اللي Claude كان عدّلها في المحادثة نفسها [cc-checkpointing]. استخدم git عشان ترجعها. العزل كان في الـ context بس.

Key takeaways

  • الـ subagent = context منفصل + system prompt خاص + رسالة مهمة؛ بيرجّع الرسالة الأخيرة بس.
  • مابيشوفش تاريخ المحادثة (إلا الـ fork)؛ أي قرار مهم لازم يتكتب في رسالة المهمة.
  • بيوفّر في الـ context الرئيسي، مش في الـ tokens.
  • العزل في الـ context، مش في الملفات.
  • اطلب شكل نتيجة فيه أدلة واستثناءات، عشان الخلاصة ماتاكلش التفاصيل المهمة.

Review questions ​

  1. إيه اللي بيدخل الـ subagent في أول ما يشتغل، وإيه اللي مابيدخلش؟
  2. ليه Explore وPlan بيبدأوا من غير CLAUDE.md؟
  3. إيه الفرق بين subagent عادي وfork؟
  4. ليه تعديلات الـ subagent ممكن تفضل بعد /rewind؟
  5. إمتى تستخدم skill بدل subagent، وإمتى تستخدم الاتنين مع بعض؟
