Agent Loop ​

ReviewedPublishedAI-assisted

The control loop in which an LLM repeatedly chooses a tool call or a final answer, while the surrounding program runs the tools and feeds the results back.

Also known as
agentic loop, tool-use loop, ReAct-style loop

Definition ​

Definition: Agent loop

الـ agent loop هي الدورة اللي فيها الـ LLM بيقرر في كل خطوة حاجة من اتنين: يطلب تشغيل tool، أو يدي إجابة نهائية. البرنامج اللي حوالين الموديل (الـ harness) هو اللي بينفذ الـ tool فعلًا، ويرجّع النتيجة للموديل في الـ conversation history، والدورة تتكرر لحد ما الموديل يخلص أو حد أقصى يوقفها.

يعني باختصار (تلخيص للشرح، مش اقتباس): Agent = LLM + Tools + Loop. الـ agent مش موديل مختلف عن الـ LLM؛ هو نظام بنبنيه حوالين الـ LLM عشان يقدر ينفّذ ويشوف النتيجة ويكمّل. والمقال بيقولها كده: الموديل عمره ما بيلمس الـ filesystem؛ هو بيطلب إن حاجات تحصل، والكود بتاعك بيخليها تحصل [eric2026post].

Learning objectives ​

  • تشرح الفرق بين LLM بيرد مرة واحدة وagent بيكمّل لحد ما المهمة تخلص.
  • تحدد مين بيعمل إيه: الموديل بيقرر، والـ harness بينفذ.
  • تكتب loop بسيطة وتعرف إمتى لازم تقف.
  • تفهم ليه تكلفة الـ tokens بتزيد بسرعة مع عدد الخطوات.

Intuition ​

تخيل إنك بتكلم مهندس شاطر جدًا في التليفون، بس هو مش قدامه الكمبيوتر. تقوله "صلّح الـ bug في app.py". هو مايقدرش يفتح الملف بنفسه، فيقولك: "اقرالي app.py". إنت تقراله، فيقولك: "غيّر السطر ده بالسطر ده". إنت تغيّر، وتقوله "تم". يقولك: "شغّل الـ tests". وهكذا لحد ما يقولك "خلاص، الـ bug اتصلح".

المهندس هنا هو الـ LLM، وإنت الـ harness: إيديه اللي بتلمس الكمبيوتر. وكل اللي اتقال في المكالمة لحد دلوقتي هو الـ conversation history.

التشبيه ده بيبوظ عند نقطة مهمة: المهندس الحقيقي فاكر المكالمة. الـ LLM API في التصميم ده مش فاكر حاجة لوحده؛ إحنا بنبعتله المكالمة كلها من الأول في كل مرة [eric2026post].

Formal explanation ​

خلّي Ht هي الـ history قبل الخطوة رقم t، وH0 فيها الـ system prompt ورسالة المستخدم. في كل خطوة:

yt=LLM(Ht),Ct=parse(yt)

وyt هنا هو رد الموديل كنص، وCt هي الـ tool calls اللي اتفهمت منه.

  • لو Ct فاضية: yt هي الإجابة النهائية، والـ loop تقف.
  • لو مش فاضية: الـ harness بينفذ كل call ويجمع النتائج Rt، وبعدين:
Ht+1=Ht‖yt‖Rt

يعني بنضيف رد الموديل ونتايج الأدوات في آخر الـ history (‖ معناها "نلزق في الآخر").

Why token cost grows fast ​

ده استنتاج حسابي، مش رقم من المحاضرة. لو كل خطوة بتضيف تقريبًا k tokens للـ history، يبقى الـ call رقم t بيبعت حوالي |H0|+tk tokens. فإجمالي الـ input tokens على n خطوات:

∑t=0n−1(|H0|+tk)=n|H0|+kn(n−1)2

الجزء التاني بيكبر مع n2. عشان كده الـ agent اللي بيعمل 50 خطوة مش أغلى من اللي بيعمل 5 بعشر مرات بس؛ ممكن يبقى أغلى بكتير. ودي من الأسباب اللي بتخلي الـ harnesses الحقيقية تعمل compaction وتستخدم subagents (شوف Agent Harness). وخلي بالك: الـ prompt caching في بعض الـ APIs بيرخّص سعر الجزء المتكرر من الـ input، بس الموديل لسه بيقرا الـ context كله، فحجمه هو هو.

When the loop must stop ​

Stop conditionWho triggers itExample
Final answerالموديل: رد من غير tool calls"Done. I updated app.py."
Step limitالـ harnessmax_steps = 25
Unrecoverable errorالـ harnessأداة مش موجودة، أو صلاحية مرفوضة
User interruptالمستخدمCtrl+C

في كود المحاضر المنشور، الـ inner loop بتقف بأول شرط بس، والـ outer loop بتقف كمان بـ Ctrl+C عند الـ prompt؛ مفيش step limit ولا error handling [eric2026post].

Technical example ​

الـ loop دي مختصرة من الـ lab (Minimal coding agent)، واتشغلت هناك فعلًا بموديل scripted:

python
conversation = [{"role": "system", "content": system_prompt}]
conversation.append({"role": "user", "content": "Open hello.py and add a multiply function."})

for step in range(max_steps):                      # safety limit, not in the lecture version
    reply = llm(conversation)                      # the model only sees what we send
    conversation.append({"role": "assistant", "content": reply})
    calls = extract_tool_invocations(reply)        # text -> [(name, args)]
    if not calls:                                  # no tool call means "I am done"
        print(reply)
        break
    for name, args in calls:
        result = TOOL_REGISTRY[name](**args)       # the harness, not the model, runs the tool
        conversation.append({"role": "user", "content": f"tool_result({json.dumps(result)})"})

Diagram ​

البنفسجي هو الموديل، والبرتقالي هو الـ harness، والأزرق هو المستخدم. لاحظ إن السهم الوحيد اللي بيرجع لفوق بيعدّي على "Step limit reached?": ده اللي بيمنع الـ infinite loop.

Limitations and common misconceptions ​

"The LLM runs the tool"

غلط. الموديل بيطلع نص بيطلب الأداة. اللي بيفتح الملف فعلًا هو كود Python في الـ harness [eric2026post]. ولو الكود ده مش موجود، كتابة اسم الأداة في الـ prompt مش هتعمل أي حاجة.

  • "Agent = a smarter model." لأ. نفس الموديل ممكن يبقى chatbot أو agent حسب الـ harness اللي حواليه.
  • "No tool call means success." الـ loop البسيطة مابتفرّقش بين "خلصت" و"حاولت أطلب tool بس الصيغة باظت". الـ lab أثبت إن الـ call الغلط بيتطبع للمستخدم كأنه إجابة نهائية.
  • "More steps means more thinking." كل خطوة بتزود التكلفة (شوف المعادلة فوق) وبتزود فرصة إن الموديل يتوه. الأفضل أدوات أوضح وخطوات أقل.
  • ReAct. الـ loop دي قريبة من فكرة ReAct (reason ثم act ثم observe)، بس المحاضرة ماستخدمتش المصطلح ده، ومش لازم الموديل يكتب الـ reasoning بتاعه صراحة عشان الـ loop تشتغل.

Exercises ​

Exercise: Count the messages

مستخدم طلب مهمة، والـ agent عمل 3 tool calls (كل واحدة في رد لوحدها) وبعدين رد رد نهائي. كام رسالة في الـ history في الآخر، لو بدأنا بـ system prompt؟

Solution

1 system + 1 user + 3 × (assistant + tool result) + 1 final assistant = 9 رسائل. نفس الحساب بيدي 7 رسائل لتشغيل الـ lab بخطوتين، وده اللي ظهر فعلًا في الـ output.

Exercise: Estimate the cost

لو |H0|=2000 tokens وكل خطوة بتضيف k=1500 token، احسب إجمالي الـ input tokens لـ 10 خطوات ولـ 40 خطوة بالمعادلة اللي فوق. (الأرقام دي افتراضية للتمرين.)

Solution
  • n=10: 10×2000+1500×45=87,500 token.
  • n=40: 40×2000+1500×780=1,250,000 token.

عدد الخطوات زاد 4 مرات، والتكلفة زادت حوالي 14 مرة.

Key takeaways

  • الـ agent هو LLM + tools + loop؛ الموديل بيقرر والـ harness بينفذ.
  • كل نتيجة tool لازم ترجع للـ history، وإلا الموديل مش هيعرف حصل إيه.
  • الـ history بتتبعت كاملة في كل call، فحجم الـ input اللي بيتعالج بيكبر تقريبًا مع مربع عدد الخطوات (الـ caching ممكن يقلل السعر، مش الحجم).
  • لازم شروط وقف غير "الموديل خلص": step limit وerror handling.

Review questions ​

  1. ليه الـ agent محتاج loop أصلًا، وليه call واحد للموديل مش كفاية؟
  2. إيه اللي يحصل لو نسينا نضيف نتيجة الـ tool للـ history؟
  3. اشرح ليه 40 خطوة ممكن تكلف أكتر من 4 أضعاف 10 خطوات.
  4. اذكر حالة يكون فيها "مفيش tool call" مش معناه إن المهمة خلصت.
