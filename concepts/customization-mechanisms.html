Choosing Where an Instruction Lives ​

ReviewedPublishedAI-assisted

Claude Code has seven places to put an instruction (CLAUDE.md, rules, skills, subagents, hooks, output styles, an appended system prompt); they differ in when they load, what survives compaction, how much context they cost, and whether the behaviour is requested or enforced.

Definition ​

Definition: Customization mechanism

مكان بتحط فيه تعليمة للـ coding agent. في Claude Code فيه سبعة: CLAUDE.md، وrules، وskills، وsubagents، وhooks، وoutput styles، والـ appended system prompt [segner2026, intro]. الفرق بينهم مش في الكلام اللي بتكتبه، الفرق في تلات حاجات: التعليمة بتدخل الـ context إمتى، وبيحصلها إيه في الـ compaction، وبتكلّف context قد إيه. وفيه سؤال رابع بيفرّق كل ده: الحاجة دي طلب من الموديل ولا حاجة الـ harness بينفذها بنفسه؟

Learning objectives ​

  • تعدّ السبع آليات وتقول كل واحدة بتتحمّل إمتى وبتعيش بعد الـ compaction ولا لأ.
  • تفرّق بين model instruction (طلب ممكن يتنسي) وexecution enforcement (hook بيشتغل كل مرة).
  • تختار بين nested CLAUDE.md وpath-scoped rule، وبين skill وsubagent.
  • تعرف الخمس "smells" اللي بتقول إن تعليمة في المكان الغلط.

Intuition ​

تخيّل مهندس جديد في الفريق. فيه حاجات لازم يعرفها من أول يوم (المشروع بيتبني إزاي)، وحاجات يعرفها لما يفتح فولدر معيّن (قواعد الـ API)، وحاجات يرجعلها لما يحتاجها (checklist الـ release)، وحاجات تبعتها لزميل يرجّعلك الخلاصة (بحث طويل في الـ logs)، وحاجات مش بتسيبها لذاكرته خالص: الـ CI بيشغّل الـ linter غصب عنه. كل نوع ليه مكان، ولو حطيت كله في ورقة الترحيب، الورقة تطول ومحدش يقراها كويس.

Formal explanation ​

The seven mechanisms side by side ​

الجدول ده ملخّص جدول المقالة [segner2026, summary table]:

ملاحظة على الجدول: المقالة نفسها مش متسقة في تكلفة الـ output styles؛ الجدول بيقول "High" والقسم بيقول "moderate context cost" لأنها بتتعمل cache [segner2026, Output styles]. الاتنين صح من زاوية: هي بتاخد مساحة طول الوقت، بس بتتقري من الـ cache.

CLAUDE.md: facts Claude should hold all the time ​

CLAUDE.md مكان الحقايق اللي محتاجها في كل مهمة: أوامر الـ build، وشكل الـ monorepo، وconventions الفريق. والنصيحة: أقل من 200 سطر، وليه owner، وتتراجع تعديلاته زي الكود؛ واعتبره index بيشاور على ملفات تانية [segner2026, CLAUDE.md files]. والـ docs بتقول نفس الرقم، وبتضيف إن الـ imports بتنظّم الملف بس مابتقللش تكلفته، لأن الملفات المستوردة بتتحمّل معاه [cc-memory, Write effective instructions].

في الـ monorepo: كل فريق ليه CLAUDE.md في فولدره، والمطوّر يقدر يتخطى ملفات فرق تانية بـ claudeMdExcludes. ولو قاعدة لازم تنطبق على كل repos الشركة (security، compliance)، فيه CLAUDE.md مركزي بيتوزع على الأجهزة ومحدش يقدر يستثنيه [segner2026, CLAUDE.md files].

Rules: constraints, optionally scoped to paths ​

الـ rules ملفات Markdown في .claude/rules/. من غير paths هي ميكانيكيًا زي CLAUDE.md: بتتحمّل أول الـ session وبتتحقن تاني بعد الـ compaction [segner2026, Rules; cc-memory, Set up rules]. بـ paths بتتحمّل بس لما Claude يقرا ملف مطابق:

markdown
---
paths:
  - "src/api/**"
  - "**/*.handler.ts"
---
All API handlers must validate input with Zod before processing.

Nested CLAUDE.md ولا rule؟ الـ nested ملف لفولدر كامل ليه conventions خاصة؛ الـ path-scoped rule لقيد بيلمس ملفات متفرقة في أماكن كتير (زي "migrations are append-only") [segner2026, Rules].

Skills and subagents: procedure here, or work over there ​

الاتنين بيبدأوا رخاص: الاسم والوصف بس. الفرق في فين الشغل بيحصل:

  • الـ skill بتتحمّل جوه المحادثة الرئيسية، فتشوف كل خطوة وتوجّهها. مكانها: deploy workflows، وrelease checklists، وreview processes [segner2026, Skills].
  • الـ subagent بيشتغل في context جديد، والـ body بتاعه عمره ما بيدخل المحادثة الرئيسية؛ اللي بيرجع آخر رسالة بس. مكانه: شغل جانبي هيملا المحادثة بنتايج وسيطة مش هترجعلها، زي deep search أو تحليل logs أو dependency audit [segner2026, Subagents]. وممكن يتداخلوا لحد خمس مستويات، بس ده مش سبب تستخدمهم.

تفاصيل أكتر في Agent Skills وSubagents.

Hooks: triggered every time, decided by code or by a model ​

الـ hooks بتتسجّل في settings.json أو managed policy settings أو frontmatter بتاع skill/agent، وأنواعها خمسة: command، وhttp، وmcp_tool، وprompt، وagent. كلها بتتشغّل deterministically على الـ event، بس أول تلاتة بينفذوا كود ثابت، وآخر اتنين بيستخدموا حكم Claude [segner2026, Hooks]. يعني "التوقيت مضمون" مش معناه "القرار مضمون".

وتكلفتها قليلة لأنها كود الـ harness بيشغّله مش تعليمات في الـ context. اللي بيرجع للـ context هو الـ stderr بتاع hook عمل block (عشان Claude يعرف ليه اتمنع)، وغير كده مفيش حاجة إلا لو الـ config رجّعها صراحة [segner2026, Hooks]. وPreToolUse hook يقدر يمنع أي tool call بـ exit code 2.

Output styles and the appended system prompt: global changes ​

الاتنين بيلمسوا الـ system prompt، بس بشكل مختلف جدًا:

  • الـ output style بيستبدل جزء الـ system prompt الافتراضي. أي custom style بيشيل تعليمات Claude Code الخاصة بالـ software engineering (إزاي يحدد نطاق التغيير، والـ comments، والأمان، وإنه يشغّل الـ tests قبل ما يقول خلصت) إلا لو حطيت keep-coding-instructions: true [segner2026, Output styles][cc-output-styles, custom styles]. وقبل ما تكتب واحد، فيه built-in: Proactive وConcise وExplanatory وLearning [cc-output-styles, Built-in output styles].
  • الـ --append-system-prompt بيضيف بس، مابيغيّرش الدور، ولـ invocation واحدة [segner2026, Appending the system prompt] [cc-cli, System prompt flags]. وكل ما تزوّد تعليمات بالطريقة دي، الالتزام بيها بيقل، خصوصًا لو متعارضة.

Five signs an instruction is in the wrong place ​

المقالة بتختم بخمس علامات [segner2026, When to use each method]:

You wrote…Move it to
"Every time X, always do Y" في CLAUDE.mdhook: الموديل وهو بيختار يشغّل formatter غير إن الـ formatter يشتغل لوحده
"Never do this" في CLAUDE.mdguardrail deterministic (hook أو permissions)، لأن التعليمة ممكن تتنسي في session طويلة أو تحت prompt injection
procedure من 30 سطر في CLAUDE.mdskill
قاعدة خاصة بـ src/api/** من غير pathspath-scoped rule
تفضيل شخصي في CLAUDE.md المشروعالملف الـ user-level

Technical example ​

script صغير بالـ standard library بيدوّر في CLAUDE.md على العلامات اللي فوق. ده heuristic من عندي مبني على قايمة المقالة، مش أداة رسمية: الـ regex بيلاقي كلمات، مش نوايا.

python
import re
import sys
from pathlib import Path

SMELLS = [  # (pattern, where it probably belongs)
    (r"\b(every time|always run|after (every|each))\b", "hook: it must happen every time"),
    (r"\b(never|must not|do not ever)\b", "hook or permission rule: a guardrail, not a request"),
    (r"(src|app|lib|api)/\S*|\*\*/|\*\.\w+", "path-scoped rule: it names specific files"),
    (r"\b(I prefer|my preference|personally)\b", "user-level file: a personal preference"),
]


def audit(text: str, max_lines: int = 200, max_steps: int = 8):
    lines = text.splitlines()
    findings = []
    if len(lines) > max_lines:
        findings.append((0, f"{len(lines)} lines (> {max_lines}): move detail out"))
    steps = 0
    for n, line in enumerate(lines, start=1):
        steps = steps + 1 if re.match(r"\s*\d+\.\s", line) else 0
        if steps == max_steps + 1:
            findings.append((n, f"procedure longer than {max_steps} steps: skill"))
        for pattern, where in SMELLS:
            if re.search(pattern, line, flags=re.IGNORECASE):
                findings.append((n, where))
    return findings


if __name__ == "__main__":
    for n, msg in audit(Path(sys.argv[1]).read_text(encoding="utf-8")):
        print(f"line {n}: {msg}")

على CLAUDE.md فيه "Always run ruff after every edit."، و"Never push to main."، وقاعدة لـ src/api/، و"I prefer short commit messages."، وrelease checklist من 9 خطوات، الـ output (اتشغّل فعلًا يوم 2026-11-08):

text
line 3: hook: it must happen every time
line 4: hook or permission rule: a guardrail, not a request
line 5: path-scoped rule: it names specific files
line 6: user-level file: a personal preference
line 16: procedure longer than 8 steps: skill

Diagram ​

اقرا الرسمة كتلات مجموعات: "Enforced by the harness" حاجة الـ harness بينفذها بنفسه، و"Loaded only when needed" حاجات بتدخل الـ context وقت الحاجة بس، و"Always in context" حاجات بتدفع تمنها في كل request. كل ما تنقل تعليمة من "Always" لـ "Loaded only when needed"، بتوفّر context؛ وكل ما تنقل قاعدة "لازم" لـ "Enforced"، بتحوّلها من طلب لضمان. التقسيمة دي من عندي، مبنية على جدول المقالة [segner2026, summary table].

Limitations and common misconceptions ​

  • "لو التعليمة في الـ context يبقى هتتنفذ." لأ. وجود التعليمة حاجة والالتزام بيها حاجة تانية، والمقالة نفسها بتقول إن Claude "will follow the instruction most of the time" [segner2026, When to use each method].
  • "Hook يبقى أمان." الـ hook طبقة. منع النص rm -rf مش بيمنع كل الطرق لنفس النتيجة؛ الحماية الحقيقية permissions وsandbox وبعدين hooks.
  • "Subagents أكتر = نظام أشطر." كل subagent ليه وقت وتنسيق؛ المهمة الصغيرة أحسن في الـ context الرئيسي.
  • الجدول خاص بـ Claude Code وبتاريخه. harnesses تانية (زي Factory Droid) ليها أسماء وسلوك مختلف؛ شوف Factory AGENTS.md.
  • الأرقام إرشاد. "أقل من 200 سطر" توصية، مش حد تقني.

Exercises ​

Exercise: Place each instruction

لكل واحدة اختار مكانها: (1) "المشروع FastAPI وPostgreSQL". (2) "شغّل ruff format بعد أي تعديل في ملف Python". (3) "كل ملفات *.sql في أي مكان لازم تبقى append-only". (4) checklist الـ release من 12 خطوة. (5) "دوّر في 2 GB logs على سبب الـ timeout ورجّعلي الخلاصة". (6) "في الـ session دي راجع بس ومتعدّلش".

Solution

(1) root CLAUDE.md. (2) PostToolUse hook. (3) path-scoped rule بـ paths: ["**/*.sql"]، لأنها ملفات متفرقة مش فولدر واحد. (4) skill. (5) subagent. (6) --append-system-prompt [segner2026, When to use each method; cc-cli]. وفي (6) لو عايز ضمان فعلي إنه مايعدّلش، استخدم permission mode للقراءة بس، لأن التعليمة طلب مش منع.

Exercise: The style that broke verification

زميلك عمل custom output style عشان الردود تبقى أقصر. بعدها لاحظ إن Claude بقى بيقول "خلصت" من غير ما يشغّل الـ tests. إيه اللي حصل، وإيه الحل؟

Solution

الـ custom style بيستبدل تعليمات الـ software engineering الافتراضية، ومنها عادة التحقق قبل إعلان الانتهاء. الحل keep-coding-instructions: true في الـ frontmatter، أو الـ built-in Concise بدل style جديد [segner2026, Output styles; cc-output-styles].

Exercise: What survives compaction

بعد compaction في session طويلة: إيه اللي لسه موجود من (أ) root CLAUDE.md، (ب) backend/CLAUDE.md اتقرا من ساعة، (ج) path-scoped rule، (د) 6 skills استخدمتهم، (هـ) output style؟

Solution

(أ) بيتقري تاني. (ب) بيضيع لحد ما تلمس ملف في backend/ تاني. (ج) بتتحقن تاني حسب الجدول. (د) بيرجعوا لحد budget مشتركة، والأقدم بيقع الأول. (هـ) عمره ما بيتضغط لأنه في الـ system prompt [segner2026, summary table].

Key takeaways

  • السبع آليات بيختلفوا في التحميل، والـ compaction، والتكلفة، ومين بينفذ.
  • اللي لازم يحصل كل مرة يبقى hook؛ اللي ممنوع تمامًا يبقى guardrail مش جملة.
  • CLAUDE.md قصير وفيه حقايق دايمة؛ الـ procedures skills؛ القيود الخاصة بملفات rules بـ paths.
  • اختار أضيق آلية تعمل المطلوب.

Review questions ​

  1. ليه unscoped rule "mechanically identical" لكتابة نفس الكلام في CLAUDE.md؟
  2. إيه الفرق بين hook من نوع command وhook من نوع prompt لو الاتنين بيتشغّلوا على نفس الـ event؟
  3. إمتى تختار skill بدل subagent لنفس الـ code review؟
  4. ليه custom output style ممكن يغيّر سلوك حاجات مالهاش علاقة بالأسلوب؟
