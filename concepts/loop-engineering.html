Definition ​

Definition: Loop engineering

الـ loop engineering هو تصميم الـ loop الخارجية اللي بتشغّل الـ coding agent تاني وتالت لحد ما المهمة تخلص فعلًا. التصميم ده بيجاوب على أربع أسئلة: كل iteration بتشوف إيه، شغلها بيتراجع إزاي، إيه اللي بيتنقل من iteration للي بعدها، وإمتى الـ loop لازم تقف.

المصطلح نفسه مش standard؛ ده اسم مريح لمجموعة أفكار، أشهرها الـ "Ralph" technique. Geoffrey Huntley وصفها في أبسط صورة بإنها "a Bash loop": سطر واحد بيبعت نفس الـ prompt للـ agent تاني كل ما يخلص [huntley2025ralph].

والفكرة المهمة: الـ agent اللي بيشتغل مدة أطول مش أحسن تلقائيًا. الهدف إن كل iteration تضيف تقدم متأكدين منه، مش إن عدد الـ iterations يكبر.

Learning objectives ​

  • تفرّق بين الـ inner loop (الموديل والأدوات جوه session واحدة) والـ outer loop (تكرار المهمة كلها).
  • تصمم شروط وقف حقيقية: limit، وbudget، وكشف إن مفيش تقدم، وescalation لإنسان.
  • تفهم ليه "الـ agent قال خلصت" مش دليل، وإيه اللي يعتبر دليل.
  • تختار بين الأدوات الموجودة فعلًا (اتراجعت يوم 2026-11-07) وتعرف حدود كل واحدة.

Intuition ​

افتكر الـ Agent Loop: الموديل بيطلب tool، والـ harness بينفذ، والدورة تتكرر لحد ما الموديل يرد من غير tool call. دي الـ inner loop، وبتخلص لما الموديل يحس إنه خلص.

الـ outer loop زي مشرف في ورشة. العامل يقوله "خلصت". المشرف مايصدقش الكلام؛ بيشغّل الماكينة ويقيس القطعة. لو القياس غلط، بيرجّعله القطعة ومعاها رقم القياس بالظبط. ولو العامل رجع بنفس الغلطة تلات مرات، المشرف مابيفضلش يرجّعها للأبد؛ بيوقف ويكلم المهندس.

العامل هو الـ agent. والقياس هو الـ tests والـ lint والـ type checks. والمهندس هو إنت.

Formal explanation ​

Inner loop versus outer loop ​

Inner loopOuter loop
Unit of repetitiontool call واحدiteration كاملة على المهمة
Who decides to continueالموديل (يطلب tool ولا لأ)الـ controller (script، hook، أو orchestrator)
Typical stopرد من غير tool callchecks نجحت، أو limit، أو budget، أو مفيش تقدم
Where it livesجوه الـ harnessفوق الـ harness، أو plugin جواه

الـ outer loop مش بديل للـ inner loop؛ كل iteration فيها inner loop كاملة.

The four design questions ​

  1. Input per iteration. نفس الـ prompt كل مرة، ولا prompt بيتحدّث من ملف progress؟ في الـ Ralph الأصلي، الـ prompt ثابت والـ plan والـ specs بيتقروا من جديد في كل loop، والـ agent بيختار أهم حاجة واحدة يشتغل عليها [huntley2025ralph].
  2. Verification (backpressure). إيه اللي بيرفض الشغل الناقص؟ Huntley بيسميها backpressure: tests وtype checkers وstatic analysis بترفض الكود الغلط بسرعة [huntley2025ralph].
  3. State carried over. التقدم بيتحفظ فين؟ في الـ conversation نفسها، ولا في الملفات والـ git وملف progress؟ الفرق ده بيحدد هل الـ context بيتراكم ولا بيبدأ fresh.
  4. Stop conditions. إمتى نقف؟ الـ completion signal لوحده مش كفاية (تحت)، فلازم max iterations، وbudget، وكشف التكرار، وescalation.

البنفسجي هو الموديل، والبرتقالي هو الـ controller، والأخضر هو الـ checks والـ commits اللي بتعمل "evidence"، والأحمر هو الوقف. لاحظ إن الطريق الوحيد لـ "Done" بيعدّي على checks خارجية، مش على كلام الـ agent.

Two ways to repeat: same session or fresh context ​

نفس الـ session (Stop hook). الـ plugin الرسمي ralph-loop بيشتغل جوه الـ Claude Code session الحالية. بيحط state file في .claude/ralph-loop.local.md، ولما Claude يحاول ينهي الـ turn، الـ Stop hook بيمنعه ويبعتله نفس الـ prompt تاني. الشغل اللي فات بيفضل موجود في الملفات والـ git history [ralph-loop-plugin].

الميزة إنه بسيط ومش محتاج script برا. العيب إن الـ conversation نفسها بتكبر مع كل iteration، فلازم الـ compaction يشتغل في النص (شوف Context Window Observability).

Fresh context (outer script). أدوات زي wiggumdev/ralph بتعمل reset للـ context window بين كل iteration والتانية، والتقدم بيتحفظ في الـ git والملفات وملف progress.txt [wiggumdev-ralph]. وGSD Core بيشغّل البحث والتخطيط والتنفيذ التقيل في subagents بـ fresh context، ويحفظ الحالة في ملفات زي STATE.md [gsd-core, README]. ده قريب من نصيحة المحاضرة: امسح الـ context بين المراحل وعدّي اللي مهم في ملفات مكتوبة (شوف Between phases: clear the context).

Making verification stronger ​

الـ feedback المفيد للـ agent هو feedback محدد: test فشل بـ input معين، مش "راجع الكود".

  • Property-based testing: Hypothesis بتولّد inputs كتير وبتدور على حالات بتكسر الكود [hypothesis]. My reading: ده بيدي الـ loop counterexample حقيقي يرجّعه للـ agent بدل كلام عام.
  • UI behaviour: playwright-python بيشغّل browser حقيقي ويختبر الصفحة نفسها، مش الـ backend بس [playwright-python].
  • Lint and test after every edit: aider بيعمل lint تلقائي لأي ملف بيعدّله، ومع --auto-test بيشغّل الـ tests بعد كل تعديل، ولو الـ command رجّع exit code مش صفر بيحاول يصلّح [aider-linttest].

Trade-offs and risks ​

Runaway loops

الـ --max-iterations في الـ ralph-loop plugin الـ default بتاعه unlimited [ralph-loop-plugin]. من غير limit، مهمة مستحيلة (أو spec ناقص) هتفضل تلف وتاكل الـ quota. حط limit دايمًا، وحط في الـ prompt نفسه "لو مخلصتش بعد كذا iteration، اكتب إيه اللي واقف".

  • False "done". الـ promise والـ exit signal كلام الـ agent عن نفسه. والـ agent ممكن "ينجّح" الـ tests بإنه يعدّلها. My reading: خلي الـ tests (أو جزء منها) برا إيد الـ agent، وراجع الـ diff على ملفات الـ tests بالذات.
  • Context accumulation. في الـ loop اللي في نفس الـ session، الـ history بتكبر كل iteration، والـ compaction بيلخّص وممكن يضيّع تفاصيل. الـ fresh-context loops بتحل ده بس بتعتمد إن ملف الـ progress مكتوب كويس.
  • Quota and cost. حتى على Max، الـ loops الطويلة بتستهلك الـ session والـ weekly limits. والـ docs بتقول إن ultracode (workflow لكل مهمة) بيوصّلك للـ limit أسرع [cc-workflows].
  • Permissions. أدوات كتير بتشغّل Claude بـ --dangerously-skip-permissions: daydemir/ralph دايمًا [daydemir-ralph]، وbenbasha/Claude-Autopilot [benbasha-autopilot]، وhseinmoussa/claude-autopilot لو فعّلته (مقفول افتراضيًا) [hseinmoussa-autopilot]. ماتشغلش ده على جهازك الأساسي من غير sandbox أو container أو worktree معزول.
  • Supply-chain trust. الـ GSD الأصلي اتعمله archive وملكيته اتغيرت في مايو 2026، والـ continuation بتنصح تمسح packages الـ gsd-build وتستخدم @opengsd/* [gsd-build; gsd-core]. والرابط اللي في الـ notes (gsd-open/get-shit-done-redux) طلع fork شخصي ماتحدّثش من يوم ما اتعمل. اتأكد من اسم الـ org والـ package قبل ما تسطّب أي حاجة.
  • Windows. الـ Stop hook بتاع الـ ralph-loop plugin bash script. على Windows ممكن bash يروح لـ WSL بدل Git Bash ويفشل، والـ README بيشرح workaround بتعديل hooks/hooks.json [ralph-loop-plugin].

Exercises ​

Exercise: Design the stop conditions

عندك مهمة: "أضف pagination لـ endpoint /users مع tests". صمّم outer loop ليها: اكتب الـ completion criteria، وتلات stop conditions غير "الـ agent قال خلصت"، وقرر هتستخدم نفس الـ session ولا fresh context.

Solution

مثال: completion = الـ tests الجديدة والقديمة نجحت، والـ lint والـ type check نضاف، والـ diff مالمسش ملفات tests قديمة. Stop: (1) max_iterations = 10، (2) نفس الـ test فشل 3 iterations ورا بعض (مفيش تقدم)، (3) الـ agent طلب حاجة مش في الـ spec (escalate). المهمة صغيرة ومترابطة، فنفس الـ session كفاية؛ لو كانت phases كتير، fresh context مع ملف progress أحسن.

Exercise: Claim or evidence

صنّف كل واحدة: claim ولا evidence؟ (1) <promise>COMPLETE</promise>، (2) pytest رجّع exit code 0، (3) الـ OpenHands critic اداك 0.82، (4) Hypothesis مالقتش counterexample في 1000 مثال، (5) commit message بتقول "all tests pass".

Solution

(1) claim. (2) evidence (بشرط إن الـ tests نفسها ماتعدّلتش عشان تنجح). (3) تقدير من موديل، أقرب لـ claim: مفيد كإشارة مش كدليل. (4) evidence، بس محدودة بالـ properties اللي اتكتبت. (5) claim.

Key takeaways

  • الـ inner loop بتقف لما الموديل يحس إنه خلص؛ الـ outer loop لازم تقف على evidence خارجي.
  • أربع قرارات: الـ input في كل iteration، والـ verification، والـ state بيتحفظ فين، وشروط الوقف.
  • الـ completion promise والـ exit signals كلام؛ الـ tests والـ lint والـ types هي الـ backpressure.
  • حط دايمًا max iterations وbudget وكشف لعدم التقدم، وشغّل الـ autonomy في sandbox.
  • راجع أي repo بنفسك: من الأدوات اللي اترشحت، واحد archived وتلاتة dormant ورابط واحد طلع fork ميت.

Review questions ​

  1. إيه الفرق بين الـ inner loop والـ outer loop، ومين بيقرر الاستمرار في كل واحدة؟
  2. ليه الـ completion promise في الـ ralph-loop plugin مايكفيش كـ stop condition؟
  3. إمتى تختار loop في نفس الـ session، وإمتى fresh context مع ملف progress؟
  4. اذكر طريقتين الـ agent ممكن "ينجح" بيهم من غير ما المهمة تخلص فعلًا، وإزاي تقفلهم.
  5. ليه الأدوات اللي شغلها الأساسي "استنى الـ usage limit" بقت أقل أهمية في الـ interactive sessions؟
