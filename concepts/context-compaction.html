Context Compaction ​

ReviewedPublishedAI-assisted

Replacing an agent's accumulated conversation history with a shorter summary so the session can continue: it cuts the cost of re-sending the window on every step, but it is lossy and can degrade decisions right after the cut.

Also known as
compaction, auto-compact, context summarization, conversation compaction

2026-11-07

Definition ​

Definition: Context compaction

الـ compaction هو إن الـ harness ياخد الـ conversation history اللي اتجمعت في الـ session ويبدّلها بملخص أقصر، والـ agent يكمّل شغله على الملخص ده بدل الأصل. بيحصل أوتوماتيك لما الـ context يقرب من حد معين، أو يدوي لما تطلبه، وفيه prompt بيحدد الملخص يتعمل إزاي، والملخص بيحل محل اللي اتلخص [cs146s-0924, 55:25].

يعني الـ compaction عملية lossy compression: أي تفصيلة مادخلتش الملخص راحت من الـ context، والـ slides بتقولها "can be lossy" [cs146s-0924].

Learning objectives ​

  • تشرح ليه الـ compaction موجود أصلًا: تكلفة الـ context التراكمية، مش بس حد الـ window.
  • تعرف إيه اللي بيعيش بعد الـ compaction في Claude Code وإيه اللي بيضيع.
  • تختار threshold بناءً على الـ trade-off بين التكلفة وجودة القرارات، مش رقم ثابت.
  • تفرّق بين الـ compaction والبدايل: session جديدة بـ artifact مكتوب، وsubagent، وverbatim tail.

Intuition ​

تخيل اجتماع شغال من الصبح. كل ما حد يسأل سؤال، حد بيقرا محضر الاجتماع كله من الأول بصوت عالي قبل ما يجاوب. ده الـ agent loop: كل خطوة بتبعت الـ history كلها تاني. بعد شوية القراية بتاخد أطول من الشغل نفسه.

الحل الطبيعي: حد يكتب ملخص ("قررنا PostgreSQL، والـ endpoint الجديد اسمه كذا، وفاضل الـ tests")، والاجتماع يكمّل بالملخص بس. أرخص بكتير. بس لو حد محتاج الجملة اللي اتقالت بالحرف الساعة 10، الملخص مش هيساعده. ولو الملخص نسي قيد زي "ماتغيرش الـ schema"، الناس هتاخد قرارات غلط من غير ما تاخد بالها.

Formal explanation ​

Why compaction exists: the context tax ​

في كل خطوة الـ agent بيبعت الـ window كلها، فالتكلفة بتتراكم مع عدد الخطوات (الحساب في Agent Loop). في الداتا الحقيقية الوحيدة اللي عندنا، الوصول لحجم context C بيكلف تراكميًا حوالي C2.55: كل مضاعفة للـ window تكلف حوالي 6 أضعاف، والـ prompt caching بيقلل الـ constant مش الـ exponent [chaves2026research, §4.1, §4.3]. وفي نفس الوقت الجزء اللي الخطوة بتستخدمه فعلًا (حسب judge آلي) فضل حوالي 6,000 لـ 8,500 token والـ window بتكبر 16 مرة [chaves2026research, §6.2]. التفاصيل في The Context Tax.

يعني الـ compaction مش بس "عشان الـ window اتملت"؛ هو كمان طريقة توقف بيها دفع تمن context مش مستخدم في كل خطوة.

What it costs: rediscovery and fog ​

بس الـ compaction ليه تمن [chaves2026research, §5.1, §7.2, §7.3]:

  • Lossy: الـ median compaction في الدراسة دي أخد 574,875 token وطلع ملخص 4,382 token، يعني 0.8% بس عاش.
  • Rediscovery: بعده الـ agent صرف حوالي 28 خطوة زيادة يعيد قراية ملفات ويرجّع حالة كان عارفها.
  • Decision quality: في أول 5 خطوات بعده، 41.9% من رسايل المستخدم كان فيها تصحيح مقابل 17.7% عادة، والارتفاع فضل 30 خطوة على الأقل، مع إن الـ tool errors ماتغيرتش. يعني الأدوات شغالة والقرارات أسوأ.

والدراسة observational ولشخص واحد، فالأرقام دي مؤشرات مش قوانين [chaves2026research, §9].

When to compact ​

الـ threshold هو trade-off: بدري أوي وإنت بتقضي وقت كبير جوه الـ fog وفي الـ rediscovery؛ متأخر أوي وإنت بتدفع تمن window ضخمة في كل خطوة. في الدراسة دي [chaves2026research, §5.1, §8, Table 2]:

QuestionWhat the data said
Cost only (28-step penalty)optimum 220k؛ من 170k لـ 316k في حدود 10%؛ تحت 110k الـ cycle بيبوظ
With decision harm (55-step penalty)optimum 314k؛ من 239k لـ 453k في حدود 10%
Early vs lateبدري بـ 90k بيكلف 1.79x، متأخر بـ 96k بيكلف 1.10x: لو مش متأكد، اتأخر
By kind of workPR 200k–250k، research 250k–300k، QA 250k–350k، building وcode understanding 300k–450k

المبدأ اللي بيتنقل لأي harness: الشغل اللي بيعتمد على نصوص حرفية (تعديلات بتطابق ملف، commands فيها connection strings) محتاج threshold أعلى أو حماية للنص ده، والشغل اللي كل خطوة فيه بتقفل على نفسها (رد على review، check في الـ browser) يستحمل compaction أبدر [chaves2026research, §6.3, §6.4].

Compaction in Claude Code ​

ده اللي الـ docs بتقوله (الإصدارات بتتغير، فراجع الـ docs قبل ما تعتمد على رقم):

  • Automatic: Claude Code بيعمل compaction لما الـ conversation توصل الـ auto-compact window. لو ماحددتهاش، ده حد الـ context بتاع الموديل؛ الموديلات اللي عندها 1M native بتعمل compaction عند حوالي 967K افتراضيًا، وSonnet 4.6 وOpus 4.6 من غير extended context عند 200K [cc-model-config].
  • Your threshold: /autocompact 300k (أو autoCompactWindow في الـ settings، أو --autocompact، أو CLAUDE_CODE_AUTO_COMPACT_WINDOW) بيحدد الحد، من 100K لـ 1M [cc-model-config].
  • Manual with focus: /compact focus on the auth bug fix بيخلّي الملخص يحتفظ باللي إنت عايزه بدل اللي الـ automatic pass بيخمّنه، وممكن تحط section اسمه "Compact Instructions" في CLAUDE.md[cc-context-window; cc-how-it-works].
  • What survives: الـ system prompt، وCLAUDE.md بتاع الـ project root، والـ auto memory بيرجعوا من الـ disk؛ وClaude Code بيعيد قراية لحد 5 ملفات آخر حاجة اتعدلت (الملف اللي فوق 5,000 token بيرجع كـ path بس)؛ والـ skills بترجع بحد 5,000 token لكل skill و25,000 إجمالي؛ والـ context اللي الـ hooks ضافته بيتلخص مع الباقي [cc-context-window].
  • What may be lost: الملخص بيحتفظ بطلباتك والـ code snippets المهمة، بس التعليمات التفصيلية من أول المحادثة ممكن تضيع. عشان كده القواعد الدايمة مكانها CLAUDE.md، مش المحادثة [cc-how-it-works].
  • Its own cost: الـ compaction نفسه request كبير لأنه بيقرا الـ history اللي بيلخصها. لو الـ cache دافي بيبقى أرخص بكتير، فالأحسن تعمله في وقفة طبيعية بين مهمتين بدل ما تستنى الـ automatic pass في نص مهمة [cc-prompt-caching].

My reading: الـ default على موديل 1M (حوالي 967K) أعلى بكتير من الـ range اللي الدراسة لقته (250k–450k). مش معنى كده إن الـ default غلط لكل الناس، بس لو بتدفع tokens كتير، /autocompact بيخليك تجرّب الـ range ده وتقيس بنفسك.

Alternatives and complements ​

  • Fresh session + written artifact: المحاضر بيميل لده: لما يشوف بضع مئات آلاف tokens، بيكتب المعلومات المهمة في ملف ويبدأ context جديد بيه. الفرق إنك إنت اللي بتختار إيه يعدّي، مش ملخص أوتوماتيك [cs146s-0929]. التفاصيل في Advanced Prompting and Context Engineering.
  • Verbatim tail: بدل ما كل حاجة تبقى ملخص صغير، تحتفظ بآخر 30k لـ 60k token زي ما هم. الدراسة بتقدّر (بالـ model مش بتجربة) إن ده أرخص بـ 25% من الانتظار لـ 600k والتلخيص الكامل، والكاتب بيقول إنه مايعرفش harness بيعرضه كـ setting [chaves2026research, §8.1, §10].
  • Fresh subagents, not forks: subagent جديد بيبدأ حوالي 30k؛ subagent متعمله fork بيبدأ من حجم الـ parent. في الدراسة، اتنين forks بدأوا من 523k و304k وأكلوا 1.14 billion token في يوم [chaves2026research, §3, §8.1].
  • External state + retrieval (my reading): القرارات والقيود ممكن تتخزن منظمة برا الـ prompt، والنصوص الحرفية تترجع من مصدرها (الملف نفسه) وقت الحاجة، فالملخص مايبقاش هو المكان الوحيد للمعلومة.

Limitations and common misconceptions ​

  • "Compaction is free." لأ: بيضيّع تفاصيل، وبيعمل rediscovery، وفي الدراسة الوحيدة اللي قاسته التصحيحات زادت أكتر من الضعف بعده [chaves2026research, §7.2].
  • "Compact as often as possible." لأ: تحت حد معين الـ agent بيقضي الـ cycle كله يتعافى، والـ windows الصغيرة جدًا مش كفء برضه [chaves2026research, §4.3, §8].
  • "Never compact; use the 1M window." على حساب الـ tokens، ده ماجابش تمنه في الدراسة: حوالي 23M token لكل disruption اتفادت [chaves2026research, §7.5].
  • "A summary keeps everything that matters." بيحتفظ بالقرارات والقيود كويس، بس مش بالنصوص الحرفية؛ 14% من الخطوات اللي اتراجعت احتاجت النص القديم بالحرف [chaves2026research, §6.4].
  • "Caching makes long context cheap." الـ caching بيرخّص كل إعادة قراية، بس إنت لسه بتشتري الـ tokens في كل خطوة [chaves2026research, §4.3].
  • الأرقام كلها من مهندس واحد على harness واحد. الأشكال غالبًا بتتنقل أحسن من الأرقام.

Exercises ​

Exercise: Pick a strategy

لكل موقف اختار: compaction بملخص، compaction مع verbatim tail، ولا session جديدة بـ artifact؟ (1) خلصت research وproposal وهتبدأ تنفيذ؛ (2) في نص refactor بتعدل 6 ملفات اتقروا من شوية؛ (3) بترد على تعليقات review على PR.

Solution

(1) Session جديدة بـ artifact: المرحلة خلصت، وإنت عايز تختار إيه يعدّي (الـ proposal اللي اتختار بس). (2) Verbatim tail، أو أجّل الـ compaction: التعديلات محتاجة نص الملفات بالحرف. (3) ملخص عادي، وممكن بدري: كل رد بيقفل على نفسه، والـ verbatim dependence في الـ PR work كانت 2%.

Exercise: Write compact instructions

اكتب section "Compact Instructions" في CLAUDE.md لمشروع API فيه قيود مهمة (ماتغيرش الـ database schema، والـ endpoints لازم backward compatible).

Solution

مثال:

markdown
# Compact Instructions

When compacting, always keep:
- Constraints: never change the database schema; keep every endpoint backward compatible.
- Decisions made so far and the reason for each.
- Files modified, and the exact names of functions and endpoints touched.
- Failing tests and the current next step.

والأحسن كمان إن القيود الدايمة تبقى في CLAUDE.md نفسه، لأنه بيترجع من الـ disk بعد الـ compaction.

Key takeaways

  • الـ compaction بيبدّل الـ history بملخص؛ أرخص، بس lossy.
  • تكلفة الـ context تراكمية: كل مضاعفة للـ window تكلف حوالي 6 أضعاف في الدراسة الوحيدة اللي قاست.
  • الضرر الحقيقي في القرارات بعد القطع، مش في الأدوات.
  • الـ threshold range حسب نوع الشغل، والـ verbatim tail ممكن يبقى knob أهم من الـ threshold.
  • القواعد الدايمة في CLAUDE.md، مش في المحادثة.

Review questions ​

  1. ليه الـ compaction بيوفر tokens حتى لو الـ window لسه مااتملتش؟
  2. إيه الفرق بين الـ rediscovery cost والـ decision-quality cost؟
  3. ليه الـ PR work يستحمل compaction أبدر من الـ building؟
  4. إيه اللي بيرجع من الـ disk بعد الـ compaction في Claude Code، وإيه اللي بيتلخص؟
  5. إمتى session جديدة بـ artifact أحسن من الـ compaction؟
